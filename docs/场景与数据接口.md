# 场景与数据接口说明

这份文档定义：控制算法每帧能拿到哪些信息、每个变量的含义和单位，以及运行记录和数据采集会存下什么。**一切以 CarSim 为准**：坐标系用 CarSim 的，单位用 CarSim 的。

---

## 1. 坐标系

CarSim 使用 ISO 8855 坐标系（右手系）：**x 向前、y 向左、z 向上**。向左为正、向右为负；航向角逆时针（向左转）为正。

```
            x（前）
            ▲
            │
   y（左）◀──●          俯视图：● = 原点
   正值      │           向左 = +y，向右 = −y
             │           左转时 Yaw 增大
```

在你的 CarSim 里核对：从原点朝 +X 出发做一次左转，`Yo` 会变成正值，`Yaw` 增大。

> 注意：SAE J670 车辆坐标系是 y 向右、z 向下，CarSim 不用它。CARLA 自己是 y 向右（左手系），平台内部会换算，你拿到的数据全部是 CarSim 坐标。

| 坐标系 | 原点 | 方向 | 和 CarSim 的关系 |
|---|---|---|---|
| **全局坐标系** | 出生点（地面上） | x 沿出生点朝向，y 向左，z 向上 | 就是 CarSim 的全局坐标系，和导出变量 `Xo`、`Yo`、`Zo`、`Yaw` 相同 |
| **自车坐标系** | CarSim 参考点（默认前轴中心的地面） | x 向前，y 向左，z 向上 | 跟着车一起移动、转动；原点就是 `Xo`、`Yo` 描述的那个点 |
| **传感器坐标系** | 传感器安装点 | x 沿传感器朝向，y 向左，z 向上 | 传感器安装位置在自车坐标系里给出 |

## 2. 单位

和 CarSim 一致，并且**自动跟随“CarSim 动力学”页设置的导出单位**（默认值如下）：

| 量 | 单位 |
|---|---|
| 位置、距离、尺寸 | m |
| 速度 | km/h |
| 角度（航向、视场角、方位角） | deg |
| 曲率 | 1/m |
| 时间 | s |

当前用的单位在 `scene["units"]` 里（见 4.1），算法按它换算，不用把 3.6 之类写死。

## 3. 在控制算法里接收

把 `control` 写成 4 个参数，每帧就会收到 `scene`（一个字典）；只写 3 个参数的算法照旧运行。

```python
class Controller:
    def control(self, exports, t, dt, scene):
        ego = scene["ego"]
        # 最近的前车：列表已按距离从近到远排好
        front = [o for o in scene["objects"] if o["rel_x"] > 0 and abs(o["rel_y"]) < 2.0]
        if front:
            gap = front[0]["gap"]          # 与前车的包围盒间距，m
            dv = front[0]["rel_vx"]        # 相对纵向速度，km/h（前方目标为负 = 在靠近）
        lane = scene.get("lane")           # 没勾车道量时没有这个键，不在车道上时为 None
        if lane is not None:
            offset = lane["offset"]        # 偏离车道中心，m（左为正）
        return [throttle, brake, steer_sw]
```

- `exports`：全部 CarSim 导出变量（按名字取值），不变。
- `scene`：见下面的定义表。
- 数据是这一帧仿真结束时的状态：CarSim 变量、障碍物、传感器数据属于**同一时刻**。

## 4. scene 定义表

### 4.1 最外层

| 键 | 含义 | 类型 / 单位 |
|---|---|---|
| `t` | CarSim 时间 | s |
| `frame` | CARLA 的世界帧号：CARLA 服务器自己一直往上数，不从本次运行开始算（记录和采集的文件名用的也是它）；算时间请用 `t` | 整数 |
| `ego` | 自车状态 | 字典，见 4.2 |
| `objects` | 自车 50 m 内的所有车和人，按 `dist` 从近到远 | 列表，每个元素见 4.3 |
| `lane` | 自车所在车道（离最近的行车道中心超过半个车道宽 + 1.5 m，例如停车场、开出路外时为 `None`） | 字典，见 4.4 |
| `collisions` | 这一帧和自车包围盒重叠的目标 | 列表，见 4.5 |
| `sensors` | 传感器数据（“场景信息”页勾选后才有） | 字典，见 4.6 |
| `units` | `exports` 和 `scene` 用的单位（“CarSim 动力学”页的设置，总是有） | 字典：`angle` "deg" / "rad"，`speed` "km/h" / "m/s"，`rate` "deg/s" / "rad/s"，`wheel_spin` "rpm" / "rad/s"，`jounce` "mm" / "m" |

### 4.2 `scene["ego"]` 自车

| 键 | 含义 | 单位 |
|---|---|---|
| `X`, `Y`, `Z` | 参考点在全局坐标系的位置（与 `Xo`、`Yo`、`Zo` 同一个点） | m |
| `Yaw` | 航向角，和 CarSim 的 `Yaw` 一样连续累加（转过一圈后是 360 多度，不折回 ±180） | deg |
| `Vx_global`, `Vy_global` | 全局坐标系下的速度分量 | km/h |
| `Speed` | 车速 | km/h |
| `length`, `width`, `height` | 车身尺寸 | m |

### 4.3 `scene["objects"][i]` 障碍物

障碍物 = CARLA 里的**车辆**（含自行车、摩托车）、**行人**，以及地图里画死的**停放车辆**。电线杆、护栏、路牌、红绿灯等不算。

| 键 | 含义 | 单位 |
|---|---|---|
| `id` | 编号，整次运行不变，用于跟踪同一目标 | 整数 |
| `type` | `"vehicle"` 车辆，`"walker"` 行人 | 字符串 |
| `parked` | 是否是地图里的停放车辆（速度恒为 0） | True / False |
| `model` | 具体模型，如 `"vehicle.tesla.model3"` | 字符串 |
| `length`, `width`, `height` | 尺寸 | m |
| `X`, `Y`, `Z` | 目标中心在全局坐标系的位置 | m |
| `Yaw` | 全局航向角，−180 ~ 180 | deg |
| `Vx_global`, `Vy_global` | 全局坐标系下的速度分量 | km/h |
| `Speed` | 目标自身的速度 | km/h |
| `rel_x`, `rel_y` | 目标中心在自车坐标系的位置（前为正，左为正） | m |
| `rel_yaw` | 相对航向 = 目标航向 − 自车航向 | deg |
| `rel_vx`, `rel_vy` | 相对速度 = 目标速度 − 自车速度，在自车坐标系下分解（前方目标 `rel_vx` 为负表示在靠近） | km/h |
| `dist` | 中心距离：自车参考点到目标中心 | m |
| `gap` | 两个包围盒之间的最近距离，接触或重叠时为 0 | m |

### 4.4 `scene["lane"]` 车道

| 键 | 含义 | 单位 |
|---|---|---|
| `width` | 车道宽度 | m |
| `offset` | 自车参考点在车道中心左侧多少（左为正） | m |
| `heading_err` | 自车航向 − 车道方向（左为正） | deg |
| `curvature` | 自车位置处车道曲率（左弯为正） | 1/m |
| `center_rel` | 前方 50 m 车道中心线，每 2 m 一点，自车坐标系 `[[x, y], ...]` | m |
| `center_global` | 同一组点，全局坐标系 `[[X, Y], ...]` | m |
| `center_curvature` | 每个中心线点处的曲率 | 1/m |
| `left_marking`, `right_marking` | 左、右车道线：`"Solid"` 实线、`"Broken"` 虚线、`"SolidSolid"` 双实线、`"SolidBroken"`、`"BrokenSolid"`、`"None"` 等 | 字符串 |
| `left_lane`, `right_lane` | 相邻车道：`"same"` 同向可行驶，`"opposite"` 对向，`"none"` 没有 | 字符串 |
| `speed_limit` | 限速 | km/h |
| `in_junction` | 自车是否在路口内 | True / False |
| `junction_dist` | 前方到下一个路口的距离（50 m 内没有时为 `None`） | m |
| `light_state` | 前方红绿灯：`"red"`、`"yellow"`、`"green"`，没有为 `None` | 字符串 |
| `light_dist` | 到该红绿灯停止线的距离 | m |

路口处前方有多个分支时，取转弯最小（最直）的那条。

### 4.5 `scene["collisions"][i]` 碰撞

每个元素：`{"id", "type", "model", "new"}`，`id` 与 `objects` 中同一目标一致；`new` 为 True 表示这一帧刚刚接触上（上一帧还没碰到）。

联合仿真时车的位置由 CarSim 决定，在 CARLA 里撞上东西车也不会停（会穿过去），所以用包围盒判断碰撞，对象是车、人、停放车辆。“场景信息”页可选：**停止运行**（提示撞到什么、第几秒）、**只记录**、**不检测**。

碰撞判断：两个包围盒在水平面上接触或重叠，**并且**高度范围也重叠（立交桥上下的车不算）。开始运行时已经贴在一起的目标，只在开始时刻的 `scene`（第一次调用 `control()` 时）算一次新碰撞（`new` 为 True），“停止运行”“只记录”也按这一次处理，之后不再重复。

### 4.6 `scene["sensors"]` 传感器数据

`{"传感器名": {"type": 类型, "data": 数据}}`，传感器名就是“传感器套件”里起的名字。

| 类型 | `data` 格式 |
|---|---|
| `rgb` 相机 | 高 × 宽 × 3，RGB，uint8 |
| `depth` 深度相机 | 高 × 宽，float32，单位 m；超过设定最大距离的像素等于最大距离 |
| `semantic` 语义分割 | 高 × 宽，uint8，每个像素是类别编号 |
| `instance` 实例分割 | 高 × 宽 × 3，uint8（R = 类别，G + B×256 = 对象编号） |
| `lidar` 激光雷达 | N × 4，float32，`[x, y, z, 强度]`，传感器坐标系（x 前、y 左、z 上），m |
| `radar` 毫米波雷达 | N × 4，float32，`[距离 m, 方位角 deg（左为正）, 俯仰角 deg, 径向速度 km/h]` |
| `imu` | `{"accel": [x, y, z] m/s², "gyro": [x, y, z] 角速度（CarSim 的角速度单位，默认 deg/s）, "compass": 角度}`，传感器坐标系 |
| `gnss` | `{"lat", "lon", "alt"}` |

某个传感器这一帧没有送来数据（5 s 内没收到）时，它的 `data` 为 `None`。

每个传感器的参数都在“传感器套件”页设置：

| 传感器 | 可设置 |
|---|---|
| 相机、深度、语义、实例 | 宽、高（px），水平视场角；深度另有最大距离（m） |
| 激光雷达 | 量程（m），线数，每秒点数，上、下视场角 |
| 毫米波雷达 | 量程（m），水平、垂直视场角，每秒点数 |
| 全部 | 安装位置 x、y、z 和朝向（自车坐标系，x 前、y 左），数量任意 |

**安装位置**用 CarSim 车身坐标系：原点在 CarSim 参考点（默认前轴中心的地面），x 向前、y 向左、z 向上；航向 `yaw` 左为正（90 = 朝左，−90 = 朝右），俯仰 `pitch` 正 = 低头（向下看），和 CarSim 的姿态角约定一致。“传感器套件”页的俯视图上，蓝色十字就是参考点。

旧版本保存的配置里，安装位置还是 CARLA 的车身坐标（原点在车身中心、y 向右）。打开旧配置时会自动换算成 CarSim 坐标，并在输出里提示，检查后保存即可。

## 5. 采样与记录

### 5.1 采样时间

- 仿真按帧推进，帧长 = “仿真步长”（例如 0.02 s）。控制算法**每帧**调用一次。
- 记录的**采样周期**可以自己设（单位 s，保存在配置里；默认 0 = 每帧采样），按帧长的整数倍执行（例如帧长 0.02 s 时 0.1 s = 每 5 帧）。改了仿真步长，采样周期不变；不是整数倍时按最接近的倍数采样，界面会提示。不能比帧长更短：要 100 Hz 就把仿真步长设为 0.01 s。联合仿真时仿真步长先对齐到 CarSim t_step 的整数倍，采样周期再按对齐后的帧长取整数倍，实际周期写在输出窗口里（例如 t_step 0.003 s：仿真步长 0.02 s → 0.021 s，采样周期 0.1 s → 0.105 s，每 5 帧）。
- 从运行开始的时刻算起：第一个采样就是开始时刻（CarSim 的开始时间 t_start，一般为 0；第一次调用 `control()` 时的状态），之后每隔一个采样周期一次（t_start 为 0、周期 0.1 s 时就是 0、0.1、0.2 s …），和 CarSim 按输出间隔写结果一样；同一个工况每次运行的采样时刻都相同。
- 被选中的帧上，CarSim 变量、障碍物、车道、传感器数据**同时**记录，时间戳相同（CarSim 时间 `t` + 帧号 `frame`）。`frame` 是 CARLA 的世界帧号（见 4.1），不从 0 开始，用来对应文件名。
- 传感器每帧都工作，只保存被选中的帧，以保证时间严格对齐；激光雷达每帧扫完整一圈。
- 运行记录和数据采集**共用**这一个采样周期。

### 5.2 运行记录（每次运行自动写）

“驾驶模式”页的**运行记录目录**（默认 `runs`，相对路径以 `carsim_carla_bridge` 目录为准；空 = 不记录）里，每次运行新建一个文件夹 `年月日_时分秒_算法文件名`，例如 `runs/20260927_101500_my_controller/`（不是自己的算法时用驾驶方式命名，如 `demo`、`carla_autopilot`；同一秒内的第二次运行加 `_2`）。以前的运行不会被覆盖。文件夹里有：

| 文件 | 内容 |
|---|---|
| `log.csv` | 每个采样时刻一行：`t`、`frame`、勾选的自车量（列名加 `ego_` 前缀，如 `ego_X`）、勾选的 CarSim 导出变量、控制算法的输出 `u1` … `un`（按 .sim 里导入变量的顺序，就是 `control()` 返回的值） |
| `log_objects.csv` | 每个采样时刻的每个障碍物一行：`t`、`frame`、`id`、`type` 和勾选的障碍物量 |
| `log_lane.csv` | 每个采样时刻一行：`t`、`frame` 和勾选的车道标量（中心线点列不写入 CSV）；没勾车道标量时不生成，车道为 `None` 的时刻没有这一行 |
| `config.json` | 这次运行实际用的完整配置（仿真步长已对齐到 CarSim t_step） |
| `算法文件名.py` | 这次运行开始时载入的算法文件的副本（只有这个文件，不含它 import 的其他文件） |
| `run.json` | 这次运行的概要，见下表；运行开始时就写一份（`end` 为 `null`），结束时补全 |

旧版本保存的配置里填的是文件名（如 `cosim_log.csv`）：文件夹建在这个文件所在的目录里，CSV 文件名沿用它（`cosim_log.csv`、`cosim_log_objects.csv`、`cosim_log_lane.csv`）。

`run.json` 的内容：

| 键 | 含义 |
|---|---|
| `map`、`spawn_index` | 地图、出生点（CarSim 原点） |
| `traffic_seed` | 运行开始时已有交通流的随机种子（“交通流”页）；没有交通流时为 `null` |
| `dynamics`、`driver`、`controller` | 动力学（`cosim` / `carla`）、驾驶方式、算法文件的路径（不是自己的算法时为 `null`） |
| `external_api` | CARLA 接口：`true` = 改版 CARLA 接口，`false` = 原版兼容模式（CARLA 物理时也为 `false`） |
| `carsim_sim`、`carsim_mock` | CarSim 的 `.sim` 文件（模拟 CarSim 或 CARLA 物理时为 `null`）、是否模拟 CarSim |
| `t_start`、`t_end` | 开始、结束时刻（CarSim 时间，s） |
| `end`、`end_reason` | 怎么结束的：`finished`（到时、碰撞停止、CarSim 结束、采集达到上限）/ `stopped`（点了停止等）/ `error`（出错），和输出窗口里相同的原因 |
| `kpi` | 运行指标，见下表 |
| `units` | CarSim 导出变量的单位（“CarSim 动力学”页），指标里的角度用它 |

运行指标（`kpi`；运行结束时也写在输出窗口里）按 CarSim 的坐标系和单位，从运行记录各采样时刻的完整场景算出（与“记录”勾了哪些量无关）；碰撞每帧都查：

| 键 | 含义 |
|---|---|
| `lane_offset_rms`、`lane_offset_max` | 车道偏移 `offset` 的均方根、绝对值的最大值，m |
| `heading_err_max` | 航向偏差 `heading_err` 绝对值的最大值（角度单位） |
| `time_off_lane` | 不在行车道上（车道为 `None`）的时间，s = 这样的采样数 × 采样周期 |
| `collisions`、`first_collision_t`、`first_collision_with` | 碰撞次数（与输出窗口里的碰撞条数相同）、第一次碰撞的时刻（s）和对象；碰撞选“不检测”时为 `null` |
| `min_gap_ahead` | 与前方目标的最小包围盒间距，m；前方 = 中心在参考点之前、横向与自车宽度有重叠的车辆 / 行人 / 停放车辆；没有这样的目标时为 `null` |
| `distance` | 行驶距离，m（相邻采样点之间直线距离之和） |
| `ay_max` | 导出变量 `Ay` 绝对值的最大值（CarSim 的导出单位，一般为 g）；没有导出 `Ay` 时没有这一项 |
| `samples`、`sample_period` | 采样数、采样周期（s） |

车道指标要有车道信息：“场景信息”页车道一栏“给算法”或“记录”至少勾一个量，否则为 `null`。

`u1` … `un` 是控制算法上一次返回的值，也就是从上一帧到这一帧一直作用在 CarSim 上、产生这一行状态的输入（和同一行里 CarSim 导出的油门、方向盘角等输入量对应）；第一行（开始时刻）还没调用过算法，这几列为空。CARLA 动力学时没有这几列。

- 每次运行一个新文件夹，不覆盖以前的记录；不要的文件夹自己删除。
- 数值保留 8 位有效数字（`t` 保留 6 位小数）。
- 大小：默认每帧采样（仿真步长 0.02 s 时 50 Hz），`_objects.csv` 里 50 m 内的每个障碍物每个采样时刻一行，交通多时一小时可到几百 MB；长时间运行时把采样周期设大（例如 0.1 s）。
- 磁盘剩余不到 10 GB 时停止写记录（仿真继续），输出窗口会提示。

检查联合仿真同步：`ego_X`、`ego_Y`、`ego_Yaw` 是车在 CARLA 里实际摆放的位置（换算到 CarSim 坐标），应该和同一行的 `Xo`、`Yo`、`Yaw` 一致。

### 5.3 数据采集（“数据采集”页打开时）

每个采样时刻同时保存下面全部内容，文件名都用帧号，互相对应：

```
数据集名称/
  相机名/000123.jpg              RGB 图像（或 .png）；语义、实例分割为 .png
  深度相机名/000123.npy          深度，float32，单位 m，超过最大距离的像素等于最大距离
  激光雷达名/000123.bin          点云 N × 4 float32 [x, y, z, 强度]，传感器坐标系，x 前 y 左 z 上（或 .npy）
  毫米波雷达名/000123.csv        每行一个探测点：距离 m, 方位角（左为正）, 俯仰角, 径向速度（角度、速度用 CarSim 单位）
  frames/000123.json             这一帧的 t、frame、勾选的 CarSim 导出变量（exports）和 ego / objects / lane / collisions，
                                 控制算法输出 action（同 5.2 的 u1 … un），IMU / GNSS 读数 sensors（格式同 4.6）
  frames.csv                     每个采样帧一行：t、frame、勾选的自车量、CarSim 导出变量和 u1 … un（同 5.2 的主文件）
  objects.csv                    每个采样帧的每个障碍物一行（同 5.2）
  lane.csv                       每个采样帧一行车道信息（同 5.2）
  calib.json                     每个传感器：相机内参 K、安装位置 mount（CarSim 车身坐标系）、
                                 外参 extrinsic_sensor_to_ego（CARLA 车身坐标系 4×4，导出用）、参考点位置
  labels/000123.json             CARLA 坐标系下的 3D 真值框：车辆、行人和地图里停放的汽车、卡车、公交车（导出 KITTI / nuScenes 用）
  ego/000123.json                CARLA 坐标系下的车辆位姿、速度、IMU / GNSS（导出用；联合仿真时速度取 CarSim 的值，原版 CARLA 也对）
  meta.json                      地图、天气、车型、采集设置、单位
```

文件名是 CARLA 的世界帧号，第一个是开始时刻（CarSim 的开始时间 t_start，一般为 0）。

`labels/`、`ego/` 和 `extrinsic_sensor_to_ego` 按 CARLA 坐标保存，只给导出 KITTI、nuScenes 用；你自己分析时用 `frames/`、三个 CSV 和 `mount` 即可，它们全部是 CarSim 坐标和单位。`ego/` 里的 `control` 只是 CARLA 这边显示用的值（联合仿真时制动恒为 0，原版 CARLA 上全部为 0），控制算法实际输出了什么看 `frames/` 的 `action`。

导出为 KITTI、nuScenes 时，按这两种格式各自的坐标规定输出。

## 6. 自定义输出：只输出勾选的变量

不是一股脑全部输出。和 CarSim 选择输出变量一样，界面上有**分组勾选清单**，每个量有两个勾选框：**给算法**（每帧交给 `control()`）和**记录**（写进运行记录和数据采集），两边分开选：

| 分组 | 可勾选的内容 |
|---|---|
| 自车 | 4.2 的每个键（给算法 / 记录） |
| 障碍物种类 | 行驶的车辆、行人、地图里的停放车辆，各自可以关掉（两边都适用） |
| 障碍物 | 4.3 的每个键（给算法 / 记录；`id`、`type` 始终保留，用来识别目标） |
| 车道 | 4.4 的每个键（给算法 / 记录）；一列全不选 = 那一方没有车道信息 |
| 传感器 | “传感器套件”里的每个传感器单独勾选是否给算法（数据采集时，套件里启用的传感器全部保存） |
| CarSim 导出变量 | “全部”或逐个勾选写进记录的导出变量（给算法的 `exports` 始终是全部） |
| 碰撞 | 停止运行 / 记录并继续 / 不检测（不检测时 `scene` 里没有 `collisions`） |

- “给算法”没勾的键在 `scene` 里就没有；“记录”没勾的键在记录文件（CSV、`frames/`）里就没有这一列。
- 勾选清单随配置文件保存（配置里 `scene` 的 `ego` / `objects` / `lane` 是给算法的，`scene.record` 里的是记录的）。
- 两边默认都勾：障碍物的 `id`、`type`、`rel_x`、`rel_y`、`rel_vx`、`rel_vy`、`dist`、`gap`；车道的 `width`、`offset`、`heading_err`、`center_rel`；自车全部；CarSim 导出变量全部。

## 7. 界面上的设置

| 位置 | 设置 |
|---|---|
| 仿真 → 场景信息 | 输出变量勾选清单（第 6 节）；碰撞处理（停止 / 记录 / 不检测）；本文档链接 |
| 仿真 → 驾驶模式 | 仿真步长（= 控制周期）；运行记录目录（空 = 不记录），下方显示最近一次运行的记录文件夹 |
| 数据 → 数据采集 | 采集开关、**采样周期**、停止条件（帧数 / 时长 / 容量）、图像格式 |
| 车辆 → 传感器套件 | 每个传感器的类型、参数、安装位置 |
| 底部面板 → 场景 | 实时显示算法这一帧收到的障碍物（俯视图 + 表格）和车道信息 |

障碍物范围固定为 50 m。
