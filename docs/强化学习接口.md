## 是什么

`carsim_carla_bridge/gym_env.py` 里的 `CoSimEnv` 是一个 [Gymnasium](https://gymnasium.farama.org/) 环境。它和运行界面、`run_cosim.py` 用的是同一套仿真（`CoSimSession`：被控对象 + CARLA + 场景信息），区别只在谁给动作：

| | 运行界面 / `run_cosim.py` | `CoSimEnv` |
|---|---|---|
| 谁给动作 | 你的控制算法的 `control()` 每帧被平台调用 | 你的训练循环调用 `step(action)` |
| 被控对象 | CarSim（或 Chrono 宝马、模拟 CarSim） | 默认服务器上的 PyChrono 宝马 E90；`config` 里可以换成模拟 CarSim |
| CARLA | 场景、渲染、传感器 | 一样 |

一次 `step` = 一个 CARLA 帧（`frame_dt`，默认 0.05 s，就是 Chrono 宝马的控制周期）：动作交给被控对象积分一帧 → 车的位姿推给 CARLA → `world.tick()` → 拿到新的场景。

它不需要界面：直接在 Python 里用，要先有一个在跑的 CARLA 服务器（原版或改版都行）。

## 最短用法

在服务器上（后端用的 Python 是 `venv_build`，已经装了 `gymnasium` 和 `torch`）：

```bash
cd ~/carla_carsim
scripts/carla_pool.sh start 2100          # 起一个私有端口的原版 CARLA（不碰界面用的 2000 / 3000）
cd carsim_carla_bridge
../venv_build/bin/python - <<'EOF'
import numpy as np, gym_env

env = gym_env.CoSimEnv(carla_port=2100)           # 第一次会加载 Town04_Opt，要几十秒
obs, info = env.reset(seed=0)
for _ in range(100):
    obs, reward, terminated, truncated, info = env.step(env.action_space.sample() * 0.1)
    if terminated or truncated:
        print(info["end_reason"])
        obs, info = env.reset()
env.close()
EOF
cd .. && scripts/carla_pool.sh stop 2100
```

`env.step` 收到的动作会被裁剪到 `action_space` 里，不会出错。

## 动作、观测、奖励、终止

**动作**：被控对象的导入变量。Chrono 宝马是 `[ax (m/s²), 前轮转角 delta (rad，左为正)]`，`action_space = Box([-4, -0.09], [4, 0.09])`（KMPPI 原工程的执行器范围；用 `action_low` / `action_high` 改）。换成模拟 CarSim（`config={"carsim": {"mock": True}}`）时是 3 个导入 `[油门, 制动, 方向盘角 deg]`，要同时给 3 维的 `action_low` / `action_high`；个数对不上时 `reset()` 会说清楚。

**观测**：默认是一个一维 `float32` 向量：全部导出变量（CarSim 的单位，顺序和“CarSim 动力学”页的导出变量列表一致）加上车道的 3 个量 `[offset (m，左为正), heading_err (deg), curvature (1/m)]`。不在车道上时这三个是 0。要别的观测：给 `obs_fn(exports, scene, t) → 数组` 和对应的 `observation_space`（两个要一起给）。

`step()` / `reset()` 返回的 `info` 里是类型固定的简单量（这样 `AsyncVectorEnv` 才能把各个环境的 `info` 按键合并）：

| `info` 的键 | 内容 |
|---|---|
| `exports` | 全部导出变量的字典（CarSim 单位，值都是 `float`） |
| `t`、`frame` | 仿真时间 (s)、回合内的步数 |
| `lane_offset`、`lane_heading_err` | 车道偏差 (m，左为正)、航向差 (deg)；不在车道上时是 `nan` |
| `speed_kmh` | 车速 |
| `n_collisions` | 这一步新撞上的目标个数 |
| `end_reason` | 回合结束时的原因，没结束是 `""` |

**完整的场景**（自车、周围的车和人、车道、碰撞、传感器数据；相机图像和激光雷达点云在这里，要在 `config["scene"]["sensors"]` 里勾选，见[场景与数据接口说明](场景与数据接口.md)）是环境的属性 `env.scene`，每一步更新。它不放进 `info`，因为它的结构随场景变（不在车道上时 `scene["lane"]` 是 `None` ……），向量环境合并 `info` 时会出错。向量环境里用 `envs.call("scene")` 取各个环境的。

**奖励**：你来写，`reward_fn(info, action) → float`；传给它的 `info` 多两项：`info["scene"]`（完整的场景）和 `info["collisions"]`（这一步新撞上的目标，每个是 `{"id", "model", ...}`）。不给时用一个例子：沿车道中心行驶得 `1 − |offset| / max_offset`（0~1），撞到东西或离开车道 −10。它只是让环境能立刻跑起来，训练自己的任务请换成你的奖励。

**终止**（回合结束）：

| | 条件 | 说明 |
|---|---|---|
| `terminated` | 撞到东西（`terminate_on_collision=True`）；离开车道（不在行车道上）；偏离车道中心超过 `max_offset`（默认 3.5 m） | 原因在 `info["end_reason"]` |
| `truncated` | 跑满 `episode_seconds`（默认 40 s）；被控对象自己到了结束时间 | |

回合结束后再调用 `step()` 会报错，要先 `reset()`。

## 重置与选项

`reset(seed=None, options=None)`：每个回合重新放一辆车（上一辆销毁）、被控对象重新开始。

| `options` 的键 | 含义 | 默认 |
|---|---|---|
| `spawn_index` | CARLA 出生点编号 | 构造时的 `spawn_index`；`None` = 地图上有四条同向车道、前方直路最长的出生点（Town04 的高速起点） |
| `init_speed` | 被控对象的初始车速 (m/s) | 构造时的 `init_speed`，20 |

环境本身没有随机性：同样的动作序列得到同样的观测（`tests/test_gym_carla.py` 核对）。要随机化出生点或初始车速，在你的训练循环里用 `options` 传。

构造函数的其他参数：`config`（和界面保存的 JSON 一样，只写要改的键，例如 `{"scene": {"collision": "off"}}`）、`map_name`（默认 `Town04_Opt`）、`episode_seconds`、`frame_dt`、`no_render`（默认 `True`，见“速度”）、`carla_host` / `carla_port`。

## 用你自己的算法当策略

平台的控制算法接口 `control(exports, t, dt, scene)` 和环境的 `info["exports"]`、`env.scene` 是同一套数据，所以现有的算法可以直接当策略：

```python
import sys; sys.path.insert(0, "controllers/kmppi_learned")
import controller, gym_env

policy = controller.Controller(); policy.reset()
env = gym_env.CoSimEnv(carla_port=2100, episode_seconds=20)
obs, info = env.reset()
done = False
while not done:
    action = policy.control(info["exports"], info["t"], 0.05, env.scene)   # [ax, delta]
    obs, r, terminated, truncated, info = env.step(action)
    done = terminated or truncated
```

`tests/test_gym_carla.py` 就是这样用 `controllers/kmppi_learned`（你的世界模型 KMPPI）跑一个 20 s 的回合，车道中心偏差和平台运行同一量级。

## 并行：多个 CARLA 服务器

一个进程一个环境，一个环境连一个 CARLA 服务器。要并行就起几个不同端口的服务器，每个环境进各自的进程（`gymnasium.vector.AsyncVectorEnv`）：

```bash
scripts/carla_pool.sh start 2100 2200 2300 2400     # 每个端口一个原版 CARLA；已在监听的跳过
scripts/carla_pool.sh status
scripts/carla_pool.sh stop 2100 2200 2300 2400      # 只关这些端口的（按起它们时记下的进程组）
```

```python
from gymnasium.vector import AsyncVectorEnv
import gym_env

ports = [2100, 2200, 2300, 2400]
envs = AsyncVectorEnv([lambda p=p: gym_env.CoSimEnv(carla_port=p) for p in ports])
obs, info = envs.reset(seed=0)                       # obs: (4, n)；info["exports"]["Vx"]: 4 个环境的车速
obs, reward, terminated, truncated, info = envs.step(actions)   # actions: (4, 2)
scenes = envs.call("scene")                          # 4 个环境各自的完整场景
```

gymnasium 1.x 的向量环境在某个环境结束（terminated / truncated）之后，**在下一次 `step` 里**才重置那个环境（那一步它的动作被忽略，返回新回合的第一个观测和奖励 0），其余环境照常前进。`tests/test_gym_vector_carla.py` 核对了这一点。

每个 CARLA 服务器约占 3 GB 显存、几个 CPU 核；每个环境还有一个 Chrono 服务进程（环境自己起、自己关）。并行实测：2 个环境（2 个 CARLA）合计 17.9 步/秒，基本线性扩展。

## 速度

一个环境约 **10 步/秒**（0.5 倍实时；机器空闲时量的）。用 `cProfile` 看过一步的时间：几乎全花在等被控对象——**Chrono 宝马积分 0.05 s 要 ~76 ms**（这台服务器的 Xeon E5-2682 v4 上，机器空闲时；单独跑 Chrono 也是这个数，和线程数无关：`OMP_NUM_THREADS` 取 1~32 都是 76~91 ms），CARLA 的 `tick` 只要 ~2 ms、场景更新 ~2 ms。所以：

- 关渲染（`no_render`，默认 `True`）**几乎不影响速度**（10.4 对 10.5 步/秒）；它的好处是不占 GPU 渲染。要相机图像就设 `no_render=False`，并在 `config["scene"]["sensors"]` 里勾选传感器。
- 要快只能**并行**（上一节），每个环境一个进程。
- `reset()` 约 2 秒（销毁旧车、放新车、被控对象重新开始），回合很短时它会成为瓶颈。

## 注意事项

- 被控对象默认是 Chrono 宝马 E90，动作的物理含义是它的 `[ax, delta]`；要用真实 CarSim 训练需要 CarSim 的服务（`config["carsim"]["remote"]`），一个 CarSim 同一时刻只能跑一个回合，不能并行。
- `reset()` 每个回合销毁并重新放一辆车、重新开始被控对象，比 `step()` 慢得多；回合太短时它会成为瓶颈。
- CARLA 服务器崩溃时 `step()` 会抛出异常，环境不会自己重启服务器；用 `carla_pool.sh` 重新起它，再新建环境。
- **训练进程崩溃**（或被强行结束）后，它的车和“同步模式”会留在 CARLA 里。下一次 `reset()` 发现出生点上有上次留下的 `hero` 车（3 m 以内）会清掉它并说一声；别的车占着出生点则报错、不动它。世界还停在同步模式时，新环境关闭时会把它放回它开始时的样子（同步），所以崩溃后最好用 `carla_pool.sh stop` / `start` 重起这个端口的服务器。
- CARLA 0.9.16 的一个已知问题：反复连接又断开 RPC 端口约 300 次服务器会崩。环境每个进程只连一次；不要用脚本去“探测”端口是否在线，看 `/proc/net/tcp` 的监听表（`carla_pool.sh` 就是这样做的）。
