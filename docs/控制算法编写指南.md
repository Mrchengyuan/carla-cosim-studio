## 1. 一句话说明

平台**每一帧**调用一次你写的 `control()`，把 CarSim 的数据（`exports`）和 CARLA 的道路、周围车辆信息（`scene`）交给你；你算出**油门、制动、方向盘**三个数返回，平台把它们送进 CarSim 算下一帧。循环、同步、记录都由平台负责，你只写“从数据算出控制量”这一部分。

最小的能运行的算法：

```python
class Controller:
    def control(self, exports, t, dt, scene):
        return [0.2, 0.0, 0.0]      # 油门 0.2，不制动，方向盘不动
```

## 2. 算法在哪里运行，谁调用它

**远程模式**（笔记本 + 云服务器）下，算法在**云服务器**上运行，不在笔记本上：

```
笔记本：界面（选算法文件、点“运行”）          云服务器：后端 backend_server.py
          CarSim 服务（CarSim 求解器）  ◀──────▶        调用你的算法 control()
                                         SSH 隧道        CARLA（场景、传感器）
```

一次运行里，平台按下面的顺序调用你的算法：

| 时刻 | 平台做什么 | 你的算法里被调用的 |
|---|---|---|
| 点“运行” | 从文件**重新加载**算法（改完文件直接再点运行就生效，不用重启任何东西）；把算法文件复制一份到这次的运行记录文件夹 | 文件顶层的代码（`import`、常数） |
| 运行开始 | 创建一个 `Controller` 对象 | `reset()`（有就调用，一次） |
| 每一帧 | CarSim 算完这一帧 → 整理 `exports`、`scene` → 调用你的算法 → 把返回值交给 CarSim 算下一帧 | `control(exports, t, dt, scene)` |
| 运行结束（到时、点停止、碰撞停止、出错） | 停车、写运行记录 | `finish(reason)`（有就调用，一次） |

实现代码在服务器的 `carsim_carla_bridge/session.py`：`load_controller()` 负责加载和检查，`CoSimSession.step()` 每帧调用。你不需要改这些文件。

本机模式（CARLA、CarSim 都在一台电脑上）用的是同一套接口，同一个算法文件两种模式都能用。

## 3. 文件的“外壳”：必须保留的三点

拿 `controllers/path_follower.py` 标一下，哪些必须保留，哪些随便改：

```python
import math                          ← 随便改：想用什么库就 import 什么

WHEELBASE = 2.66                     ← 随便改：参数，可改可删可加
TARGET_KMH = 40.0

def _curvature(p0, p1, p2): ...      ← 随便改：辅助函数，可改可删可加

class Controller:                    ← ① 保留：类名要和界面“入口”填的一样
    def reset(self): ...             ← 可选：每次运行开始调用一次

    def _steer(self, ...): ...       ← 随便改：自己的方法，可改可删可加

    def control(self, exports, t, dt, scene):   ← ② 保留：方法名和参数
        ...                                     ← 你的算法，随便写
        return [throttle, brake, sw]            ← ③ 保留：返回 3 个数

    def finish(self, reason): ...    ← 可选：运行结束时调用一次
```

**必须保留的三点：**

1. **类名和界面“入口”一致。** 入口默认填 `Controller`，你可以改成别的名字，比如 `MyMPC`，界面“入口”一栏也改成 `MyMPC`。
2. **有 `control` 方法，参数是 `(self, exports, t, dt, scene)`。**
   - 名字必须叫 `control`。
   - 参数的顺序必须是 `exports, t, dt, scene`。参数名随便起，平台按位置传。
   - 不需要 `scene` 时可以只写 3 个参数 `control(self, exports, t, dt)`，平台会自动看出来，不传 `scene`。
3. **返回 3 个数**，顺序是 `[油门, 制动, 方向盘]`，见第 8 节。

除此以外都可以自由改：`control()` 里怎么算、加多少函数和参数、拆成几个文件、用什么库。

### 另一种写法：入口是函数

不想写类也可以直接写一个函数，界面“入口”填函数名：

```python
def control(exports, t, dt, scene):
    ...
    return [throttle, brake, steer]

def finish(reason):          # 可选：结束时调用模块里的 finish
    print(reason)
```

用函数时没有 `reset()`，要在两帧之间保存数据，就用模块级变量（见第 10 节）。

## 4. 输入一：exports（CarSim 的数据）

`exports` 是一个**字典**，里面是 CarSim 的全部导出变量，**按名字取值**：

```python
v = exports["Vx"]          # 车速
yaw = exports["Yaw"]       # 航向角
sw = exports["Steer_SW"]   # 方向盘转角
```

- 变量名就是“CarSim 动力学”页导出变量列表里填的名字，要和 .sim 里的一致。
- 值是 CarSim 原样的数值，单位是 .sim 导出的单位（见第 7 节）。
- 列表里有的变量都会给你，不用另外勾选。

你现在配置的导出变量（默认单位）：

| 变量 | 含义 | 默认单位 |
|---|---|---|
| `Xo`, `Yo`, `Zo` | 车辆参考点（前轴中心地面）在全局坐标系的位置 | m |
| `Yaw` | 航向角（左转增大，连续累加，不折回 ±180） | deg |
| `Pitch` | 俯仰角（车头向下为正） | deg |
| `Roll` | 侧倾角（右侧下沉为正） | deg |
| `Vx` | 纵向车速（车体坐标） | km/h |
| `Vy` | 侧向车速（车体坐标，左为正） | km/h |
| `AVx`, `AVy`, `AVz` | 侧倾、俯仰、横摆角速度 | deg/s |
| `Steer_SW` | 方向盘转角（左为正） | deg |
| `Steer_L1`, `Steer_R1` | 左、右前轮转角 | deg |
| `Steer_L2`, `Steer_R2` | 左、右后轮转角（普通车为 0） | deg |
| `AVy_L1`, `AVy_R1`, `AVy_L2`, `AVy_R2` | 四个车轮的转速 | rpm |
| `Throttle` | 油门开度 | 0~1 |
| `GearStat` | 当前挡位 | – |
| `Jnc_L1`, `Jnc_R1`, `Jnc_L2`, `Jnc_R2` | 四个车轮的悬架行程（压缩为正） | mm |

需要别的变量（比如纵向加速度 `Ax`、侧向加速度 `Ay`、横向误差），先在 CarSim 里把它加进导出变量、重新生成 .sim，再在“CarSim 动力学”页按同样的顺序加上，算法里就能用 `exports["Ax"]` 取到。

## 5. 输入二：t 和 dt（时间）

| 参数 | 含义 | 单位 |
|---|---|---|
| `t` | 当前的 CarSim 时间，第一次调用时一般是 0 | s |
| `dt` | 每一帧的时长，等于界面“运行设置”里的“仿真步长”（例如 0.02），整次运行不变 | s |

- 积分、微分用 `dt`：`self.integral += err * dt`。
- 不要用电脑的系统时间（`time.time()`）算控制量。远程模式下仿真比实时慢，系统时间和仿真时间对不上。
- **算法要求固定的步长时**（例如 MPC、MPPI 的预测模型按 0.05 s 离散），在文件开头写一行：

  ```python
  FRAME_DT = 0.05   # s：运行时的仿真步长用它，界面上的设置不用改
  ```

  点“运行”时平台读出这个数（只读文件、不运行它），用它当这次运行的仿真步长，和界面上设的不同时在输出窗口写一句“仿真步长按控制算法 … 里的 FRAME_DT 用 0.05 s”。要直接写成数字，范围 0~0.1 s。没写就用界面上的设置。例子：`controllers/kmppi/controller.py`。

## 6. 输入三：scene（CARLA 的道路和周围目标）

`scene` 也是一个字典，里面是 CARLA 这一帧的信息。它和 `exports` 是**同一时刻**的数据。

最常用的三部分：

### 6.1 `scene["ego"]` 自车

| 键 | 含义 | 单位 |
|---|---|---|
| `X`, `Y`, `Z` | 自车参考点在全局坐标系的位置（和 `Xo`、`Yo`、`Zo` 是同一个点） | m |
| `Yaw` | 航向角 | deg |
| `Vx_global`, `Vy_global` | 全局坐标系下的速度分量 | km/h |
| `Speed` | 车速 | km/h |
| `length`, `width`, `height` | 车身尺寸 | m |

### 6.2 `scene["lane"]` 当前车道

默认给算法的：

| 键 | 含义 | 单位 |
|---|---|---|
| `width` | 车道宽度 | m |
| `offset` | 自车在车道中心的左边多少（左为正，右为负） | m |
| `heading_err` | 自车航向 − 车道方向（左为正） | deg |
| `center_rel` | 前方 50 m 的车道中心线，每 2 m 一个点，自车坐标 `[[x, y], [x, y], ...]` | m |

要在“场景信息”页勾选“给算法”才有的：

| 键 | 含义 |
|---|---|
| `curvature` | 自车位置的车道曲率（1/m，左弯为正） |
| `center_global`, `center_curvature` | 中心线的全局坐标、每个点的曲率 |
| `left_marking`, `right_marking` | 左、右车道线类型（实线、虚线……） |
| `left_lane`, `right_lane` | 左、右相邻车道：同向、对向、没有 |
| `speed_limit` | 限速 |
| `in_junction`, `junction_dist` | 是否在路口里、到下一个路口的距离 |
| `light_state`, `light_dist` | 前方红绿灯的颜色、到停止线的距离 |

**注意：`scene["lane"]` 可能是 `None`。** 车不在行车道上时（停车场、开出路外）没有车道，这时 `scene["lane"]` 是 `None`，直接写 `scene["lane"]["offset"]` 会报错。要先判断：

```python
lane = scene["lane"]
if lane is None:
    return [0.0, 2.0, 0.0]      # 没有车道：松油门、轻踩制动、方向盘回正
```

路口有多个分支时，`center_rel` 取转弯最少（最直）的那条。

### 6.3 `scene["objects"]` 周围的车和人

一个列表，自车 50 m 内的所有车辆、行人、路边停着的车，**已按距离从近到远排好**。每个元素是一个字典，默认给算法的键：

| 键 | 含义 | 单位 |
|---|---|---|
| `id` | 编号，整次运行不变，可以用来跟踪同一个目标 | – |
| `type` | `"vehicle"` 车辆，`"walker"` 行人 | – |
| `rel_x`, `rel_y` | 目标中心在自车坐标系的位置（前为正，左为正） | m |
| `rel_vx`, `rel_vy` | 相对速度（前方目标 `rel_vx` 为负表示在靠近） | km/h |
| `dist` | 自车参考点到目标中心的距离 | m |
| `gap` | 两个包围盒之间的最近距离，贴上时为 0 | m |

还可以在“场景信息”页勾选：目标的尺寸、全局位置、航向、速度、是否是停着的车等。

找本车道正前方最近的车：

```python
front = [o for o in scene["objects"] if o["rel_x"] > 0 and abs(o["rel_y"]) < 1.8]
if front:
    gap = front[0]["gap"]       # 列表已经按距离排好，第一个就是最近的
```

### 6.4 其他

| 键 | 含义 |
|---|---|
| `scene["units"]` | 当前用的单位，见第 7 节。总是有 |
| `scene["t"]` | 和参数 `t` 相同 |
| `scene["collisions"]` | 这一帧碰到的目标（碰撞检测打开时） |
| `scene["sensors"]` | 传感器数据（相机图像、激光雷达点云等），要在“场景信息”页给传感器勾选“给算法” |

### 6.5 “给算法”勾选

“场景信息”页每个量有两个勾选框：**给算法**（交给 `control()`）和**记录**（写进运行记录）。没勾“给算法”的键不会出现在 `scene` 里，取它会报错，报错信息里会写明“场景信息页没有勾选”。勾得越少，每帧越快。

## 7. 坐标系和单位

**坐标系全部用 CarSim 的**（ISO 8855）：**x 向前、y 向左、z 向上**，角度**左转为正**。

| 坐标系 | 原点 | 用在哪里 |
|---|---|---|
| 全局坐标系 | 出生点 | `Xo`、`Yo`、`scene["ego"]["X"]`、`center_global` |
| 自车坐标系 | 车辆参考点（前轴中心的地面），跟着车走 | `center_rel`、`rel_x`、`rel_y` |

记住两条就不会弄反：

- **`y` 为正在左边，为负在右边。**车在车道中心左边 0.5 m，`offset` = +0.5；这时应该向右打方向盘，方向盘转角为**负**。
- **角度左为正。**`heading_err` 为正表示车头偏向车道方向的左边。

**单位**跟随“CarSim 动力学”页的单位设置，默认 deg、km/h、deg/s、rpm、mm。当前用的单位在 `scene["units"]` 里：

```python
u = scene["units"]          # {"angle": "deg", "speed": "km/h", "rate": "deg/s", "wheel_spin": "rpm", "jounce": "mm"}
kmh = exports["Vx"] * (1.0 if u["speed"] == "km/h" else 3.6)     # 不管设置成哪种，都换算成 km/h
```

如果你确定不会改单位设置，可以直接按默认单位写（下面的例子就是这样）。

## 8. 返回值：油门、制动、方向盘

`control()` 返回一个列表，**个数和顺序与 .sim 里的导入变量（REPLACE）一致**。你现在的 .sim：

| 位置 | 含义 | 单位 / 范围 |
|---|---|---|
| 第 1 个 | 油门 | 0~1 |
| 第 2 个 | 制动：主缸压力（`IMP_PCON_BK`） | MPa，0~8 左右（8 MPa 约为紧急制动） |
| 第 3 个 | 方向盘转角 | deg，左转为正 |

- 方向盘给的是**方向盘转角**，不是车轮转角。车轮转角 × 传动比（你的车约 19）= 方向盘转角。
- 自己限幅：油门限在 0~1，方向盘限在 ±540° 左右。平台不会替你截断。
- 用元组、列表、numpy 数组都可以，只要是 3 个数。

平台每一帧会检查返回值，不对就停止运行并说明原因：

| 情况 | 报错 |
|---|---|
| 忘了写 `return` | `control() 返回了 None（是不是忘了 return？）` |
| 个数不对 | `控制算法返回了 2 个值，但 .sim 里有 3 个导入变量` |
| 返回了字典、字符串 | `control() 返回了 dict` |
| 里面有 NaN 或无穷大 | `控制算法输出了无效数值（NaN / 无穷大）` |

以后如果 .sim 里的导入变量改了（比如制动改成踏板 0~1、加了挡位），返回值要跟着改。

## 9. reset() 和 finish()

两个都是可选的。

**`reset(self)`：每次运行开始时调用一次。**用来给变量赋初值：

```python
def reset(self):
    self.integral = 0.0
    self.last_steer = 0.0
```

**`finish(self, reason)`：每次运行结束时调用一次。**`reason` 是结束原因（和界面输出里的一样），例如：

- `"达到设定的运行时长 40 s"`
- `"运行被停止"`（点了“停止”）
- `"CarSim 到达 .sim 里设定的结束时间"`
- `"碰撞：撞到 vehicle.tesla.model3（id 123）"`（碰撞时选了“停止运行”）
- 出错时是错误信息

常用来打印这次运行的统计：

```python
def finish(self, reason):
    print("结束：%s，平均偏差 %.2f m" % (reason, self.sum_offset / max(self.n, 1)))
```

`finish()` 里出错不会影响运行记录的保存，错误会显示在输出里。

## 10. 在两帧之间保存状态

积分项、上一帧的值、滤波器状态等，存在 **`self.` 上**：

```python
class Controller:
    def reset(self):
        self.integral = 0.0          # 在 reset 里给初值

    def control(self, exports, t, dt, scene):
        err = 30.0 - exports["Vx"]
        self.integral += err * dt    # 这一帧改了，下一帧还在
        ...
```

- 每次点“运行”都会创建一个新的 `Controller` 对象，上一次运行留下的值不会带过来。
- 函数写法没有 `self`，就用模块级的变量（例 4）。每次运行都会重新加载文件，模块级变量也会回到初值。

## 11. 多个文件、参数文件

**拆成多个 .py：**把它们放在**同一个文件夹**里，直接 `import`：

```
controllers/my_algo/
    controller.py      ← 界面“算法文件”填这个：controllers/my_algo/controller.py
    mpc.py             ← controller.py 里写 from mpc import solve
    params.json
```

- 同一文件夹（以及子文件夹）里的模块每次运行都会重新加载，改了辅助文件也会生效。
- 不要和常见模块重名（比如 `math.py`、`json.py`、`numpy.py`、`carla.py`），也不要和平台自己的模块重名（比如 `bridge.py`、`scene.py`、`session.py`）。重名时平台会提示改名。

**读参数文件、数据文件：**用算法文件所在的文件夹拼路径，不要写相对路径或 Windows 路径：

```python
import os
HERE = os.path.dirname(os.path.abspath(__file__))       # 算法文件所在的文件夹
params_path = os.path.join(HERE, "params.json")         # ✓ 放在算法旁边的文件
# open("params.json")                                   ✗ 相对路径是相对后端的目录算的，找不到
# open(r"E:\my\params.json")                             ✗ Windows 路径在服务器上不存在
```

读文件放在 `reset()` 或文件顶层，不要每一帧都读。

## 12. 运行环境和兼容性

远程模式下算法在**云服务器**上运行，环境是：

| 项目 | 服务器上 |
|---|---|
| 系统 | Ubuntu Linux |
| Python | 3.10 |
| 已装的库 | numpy 2.2.6、shapely、networkx、pillow、carla，以及 Python 自带的库（`math`、`json`、`collections`……） |

### 12.1 要用别的库

比如 scipy、pandas、casadi、cvxpy、torch，**先告诉管理员装到服务器上**（用清华镜像，几分钟）。没装就运行，会报：

```
加载控制算法出错：ModuleNotFoundError: No module named 'scipy'（my_ctrl.py 第 3 行）
```

### 12.2 Python 和 numpy 版本

- 你笔记本上是 Python 3.8。在 3.8 上能运行的代码，在服务器的 3.10 上基本都能运行；极少数老写法例外，比如 `collections.Mapping` 要写成 `collections.abc.Mapping`。
- 服务器上是 numpy 2。numpy 2 删掉了一些老写法，写的时候注意：

| 不要用 | 改成 |
|---|---|
| `np.float`、`np.int`、`np.bool` | `float`、`int`、`bool` |
| `np.product`、`np.cumproduct` | `np.prod`、`np.cumprod` |
| `np.alltrue`、`np.sometrue` | `np.all`、`np.any` |
| `np.NaN`、`np.Inf` | `np.nan`、`np.inf` |

### 12.3 文件编码

**用 UTF-8 保存。**VS Code、PyCharm 默认就是 UTF-8。用 Windows 记事本时，另存为选“UTF-8”。

如果文件是 GBK（“ANSI”）编码：中文只在注释里时不影响；**字符串里有中文**（例如 `print("车速")`）就会在加载时报：

```
加载控制算法出错：SyntaxError: (unicode error) 'utf-8' codec can't decode byte 0xb3 in position 0: invalid start byte（my_controller.py 第 3 行）
```

解决：另存为 UTF-8，或者在文件第一行加 `# -*- coding: gbk -*-`。

Windows 的换行格式（CRLF）没有关系，不用管。

### 12.4 服务器上不能用的东西

服务器没有屏幕和键盘，算法里不要用：

| 不要用 | 原因 | 改成 |
|---|---|---|
| `plt.show()`、`cv2.imshow()` | 没有屏幕 | 画图存成文件 `plt.savefig(...)`，或用运行记录的 CSV 画 |
| `input()` | 没有键盘，会直接报错 | 参数写在文件里 |
| `sys.exit()`、`exit()` | 不能结束后端（平台会拦下来并报错） | 用 `raise` 抛出异常说明原因 |
| 文件顶层的 `argparse` | 同上 | 参数写成常数或参数文件 |

### 12.5 计算时间

`control()` 每一帧调用一次：仿真步长 0.02 s 时，仿真时间每秒调用 50 次。算得太慢会拖慢整个仿真（结果不受影响，只是等得久）。界面“车辆状态”里的“**算法耗时**”显示每次调用用了多少毫秒。

- 耗时的初始化（读模型、建求解器）放在 `reset()` 或文件顶层，不要每帧做。
- 优化类算法（MPC）可以每几帧求解一次，中间沿用上次的结果。

2. **算法文件 .py**：点输入框右边的文件夹图标“**浏览…**”：

   - 本机模式打开系统的选择文件对话框。

3. **入口**：类名（默认 `Controller`）或函数名。用“浏览…”选文件时会自动填好；文件里有好几个带 `control()` 的类时，在选择窗口下方选一个。
4. 第一次先勾选“CarSim 动力学”页的“**模拟 CarSim**”跑一次，确认算法不报错、方向对，再取消勾选、用真实 CarSim。

**在界面里调参数（不改文件）**：文件开头的大写常数会列在“控制算法”卡片的“**算法参数**”里，例如

```python
TARGET_KMH = 40.0      # km/h，目标车速
KP, KI = 0.08, 0.02    # 车速 PI
USE_FEEDFORWARD = True
```

- 数字、文字、True / False 都行（`KP, KI = 0.08, 0.02` 这种一行两个也行）；行尾的注释显示成说明。算式（例如 `B = A * 2`）和小写的名字不列。
- 改过的值显示成蓝色，右边的按钮恢复成文件里的值，“全部恢复”一次恢复全部。改动按算法文件分别保存在配置里（换个算法文件不会串）。
- 点“运行”时，平台先加载文件，再把改过的值写回模块里的同名常数，然后才创建你的类、调 `reset()`；输出窗口会写“算法参数（界面上改过的）：TARGET_KMH = 30.0（文件里 40.0）”，`run.json` 的 `params` 也记下这次改了哪些（运行文件夹里的算法文件副本还是原来的值）。
- 所以算法要在**运行时**读这些常数（在 `reset()`、`control()` 里用 `TARGET_KMH`），改动才起作用；在模块顶层用它算出的其他值（例如 `SPEED_MS = TARGET_KMH / 3.6`）不会跟着变。
- 文件里写了 `FRAME_DT` 时，在这里改它就改了这次运行的仿真步长（见第 5 节）。

## 15. 调试：输出、报错、运行记录

### 15.1 print

`control()`、`reset()`、`finish()` 里 `print` 的内容都会显示在界面底部“**输出**”页。点“**算法**”只看算法的输出。

每帧都 print 会很多，可以隔一段时间打印一次：

```python
if int(t / 1.0) != int((t - dt) / 1.0):          # 大约每 1 秒打印一次
    print("t=%.1f 车速 %.1f 偏差 %.2f" % (t, exports["Vx"], lane["offset"]))
```

### 15.2 报错

算法出错时运行会停止，“输出”页显示错误类型、说明，以及**出错的文件和行号**，例如：

```
控制算法出错：ZeroDivisionError: division by zero（my_controller.py 第 42 行）
```

错误出在你 import 的辅助文件里时，会写成“`mpc.py 第 57 行，由 my_controller.py 第 12 行调用`”。加载阶段的错误（语法错误、缺模块、找不到入口）在动 CARLA 之前就会报出来，不会影响 CARLA。

### 15.3 运行记录

每次运行都会在服务器的 `carsim_carla_bridge/runs/` 里新建一个文件夹，名字是 `年月日_时分秒_算法文件名`，例如 `runs/20260928_111509_path_follower/`：

| 文件 | 内容 |
|---|---|
| `log.csv` | 每个采样时刻一行：时间、自车状态、全部 CarSim 导出变量、**你的算法的输出 `u1`、`u2`、`u3`**（油门、制动、方向盘） |
| `log_lane.csv` | 每个采样时刻的车道信息（偏差、航向偏差……） |
| `log_objects.csv` | 每个采样时刻的每个周围目标 |
| `run.json` | 这次运行的设置、结束原因、指标（车道偏差均方根 / 最大值、碰撞次数、行驶距离等） |
| `config.json` | 这次运行的完整配置 |
| `算法文件名.py` | 这次运行用的算法文件副本（以后改了算法，也知道当时用的是哪一版） |
| `log_debug.csv` | 你的算法 `self.debug` 里的量（写了才有，见 15.5） |
| `output.txt` | 这次运行时“输出”窗口的全部内容：你的 `print`（标 `[算法]`）、报错和调用栈、平台的提示、运行指标、结束原因，每行带时间。界面“运行对比”页的“A 的输出”直接打开它 |

用 Excel、MATLAB、Python 都能打开 CSV 分析。`u1` … `u3` 是你的算法上一帧返回的值，也就是作用在这一行状态上的输入。

### 15.4 在画面里画线：`self.draw`

算法可以把自己的规划轨迹、候选轨迹等画进 CARLA 的画面（界面视口里直接看到）。在 `control()` 里给 `self.draw` 赋一组线（入口是函数时，给模块里的全局变量 `draw` 赋值）：

```python
self.draw = [
    {"points": [[0, 0], [10, 0.5], [20, 1.5]],  # 自车坐标（和 scene 一样：x 向前、y 向左，原点在参考点），m
     "color": [255, 0, 0],                       # 红、绿、蓝 0~255，不写就是白色
     "width": 0.05},                             # 线宽 m，不写就是 0.05
    ...
]
```

- 界面底部面板的“轨迹”页签用俯视图显示同样的线，横向自动放大（CARLA 画面里一束挤在一起的线，在这里能分开看）。
- 一条线只给一个点（`"points": [[x, y]]`）时画成一个点，大小取 `width`。
- 平台在这一帧取走它（取走后 `self.draw` 变回 `None`），按**这一帧**自车的位置换算到 CARLA 里，画在路面上方 0.3 m，之后每帧重画，直到你给出新的一组；给 `[]` 就清掉。所以不用每帧都赋值：隔几帧算一次的算法只在算的那一帧赋值即可。
- 一帧最多画 5000 段（相邻两点算一段），多出来的不画，输出窗口提示一次。
- **采集数据时不画**（相机会把线拍进图像），输出窗口提示一次。
- 画线要占一些时间：几百段约 10~15 ms。格式不对时运行出错并说明是第几条线。
- 例子：`controllers/kmppi/controller.py` 每次计算后画 64 条候选轨迹（按权重从蓝到红）、最好的一条（亮红加粗）、加权平均轨迹（黄）和参考轨迹（绿）。

### 15.5 自己的曲线：`self.debug`

想看算法内部的量随时间怎么变（代价、权重、估计值、中间变量），在 `control()` 里给 `self.debug` 赋一个字典（入口是函数时，给模块里的全局变量 `debug` 赋值）：

```python
self.debug = {"代价": cost, "ESS": ess, "估计的传动比": ratio}   # 名字: 数字
```

- 界面底部“曲线”面板多出第二排，每个量一张图，实时滚动（最多画前 8 个）。
- 这次运行的文件夹里多一个 `log_debug.csv`：每个采样时刻一行，列是 `t`、`frame` 和各个名字（按第一次给出的名字定列；之后才出现的名字不写进去，输出窗口提示一次）。
- 值要是数字（numpy 的数也行）；不是数字的会被跳过并提示一次；NaN / 无穷大当作这一刻没有值。最多 32 个。
- 平台每一步读它，不会清掉它：隔几帧才算一次的算法，中间各帧沿用上一次的值。
- 例子：`controllers/kmppi/controller.py` 给出 ESS、温度、最小代价、加权平均代价、ax、前轮转角、计算耗时。

### 15.6 检验鲁棒性：干扰

真实的车有延迟和噪声，仿真默认是理想的。“驾驶模式”页算法参数下面的 **干扰** 可以在你的算法和平台之间加上：

| 干扰 | 你的算法看到的变化 |
|---|---|
| 执行器延迟 | 你返回的值晚这么久才到 CarSim（最初几帧 CarSim 收到的是你第一次的输出） |
| 测量延迟 | `exports` 和 `scene` 是这么久以前的（最初几帧是第一帧的） |
| 噪声 | 选中的导出变量加上高斯噪声（标准差，单位同导出变量） |
| 车道信息丢失 | 这一帧 `scene["lane"]` 是 `None`：算法要能处理（例如保持上一次的转角） |

延迟按帧取整（步长 0.05 s 时，0.1 s = 2 帧），最长 1 s。同样的设置和随机种子，每次运行的噪声和丢失完全一样，可以放心对比。运行记录（`log.csv`）记的是 CarSim 的真值，`run.json` 的 `disturb` 记下这次的设置，便于在“运行对比”页比较有无干扰的两次运行。实测：路线跟随算法在 Town10 上，执行器延迟 0.3 s + 测量延迟 0.2 s 时车道偏差均方根从 0.11 m 变成 0.60 m。

## 16. 常见报错和解决办法

| 报错（“输出”页） | 原因 | 解决 |
|---|---|---|
| `控制算法文件不存在：…` | 路径填错，或文件不在服务器上 | 检查“算法文件 .py”一栏（✗ 表示没找到）；确认文件已经放到服务器上 |
| `xxx.py 里没有找到 Controller；找到了：MyMPC（类）` | “入口”填的名字和文件里的类名不一样 | 把“入口”改成提示里的名字 |
| `加载控制算法出错：SyntaxError: …（第 N 行）` | 语法错误 | 看第 N 行 |
| `加载控制算法出错：ModuleNotFoundError: No module named 'xxx'` | 服务器上没装这个库，或辅助文件不在同一个文件夹 | 请管理员装库；检查辅助文件的位置 |
| `你的 xxx.py 和后端已经加载的同名模块冲突` | 文件名和已有模块重名 | 改文件名（`import` 语句一起改） |
| `控制算法出错：KeyError: 'Vxx'……导出变量里没有 'Vxx'` | 导出变量名写错，或 .sim 里没有导出这个变量 | 检查拼写；需要的话在 CarSim 里加导出变量 |
| `……场景里没有 'lane'：“场景信息”页车道一栏没有勾选“给算法”的量` | 用了没勾选的场景信息 | 到“场景信息”页勾选“给算法” |
| `控制算法出错：TypeError: 'NoneType' object is not subscriptable` | 多半是 `scene["lane"]` 为 `None`（车不在车道上）时直接取了里面的值 | 先判断 `if lane is None` |
| `control() 返回了 None（是不是忘了 return？）` | 某个分支没有 `return` | 每个分支都要返回 3 个数 |
| `控制算法返回了 2 个值，但 .sim 里有 3 个导入变量` | 返回值个数不对 | 按第 8 节返回 3 个 |
| `控制算法输出了无效数值（NaN / 无穷大）` | 除以 0、对负数开方等 | 检查计算，给分母加保护 |
| `控制算法在 control() 里调用了 sys.exit` | 用了 `sys.exit()` / `exit()` | 改成 `raise` |
| `SyntaxError: (unicode error) 'utf-8' codec can't decode byte …` | 文件不是 UTF-8 编码，字符串里有中文 | 另存为 UTF-8（见 12.3） |
| 不报错，但仿真很慢 | `control()` 算得太慢 | 看“算法耗时”；耗时的事放到 `reset()`（见 12.5） |
| 不报错，但车往反方向打轮 | 符号弄反了 | 记住：`y` 左为正，偏左时方向盘要给**负**值（见第 7 节） |

### 例 1：定速直行（最简单）

```python
"""例 1：定速 30 km/h 直行，方向盘不动。"""


class Controller:
    def reset(self):
        self.integral = 0.0                          # 每次运行开始时清零

    def control(self, exports, t, dt, scene):
        v = exports["Vx"]                            # 车速，km/h
        err = 30.0 - v                               # 目标 30 km/h
        self.integral = min(max(self.integral + err * dt, -100.0), 100.0)
        u = 0.08 * err + 0.02 * self.integral        # PI 控制
        throttle = min(max(u, 0.0), 1.0)             # 油门 0~1
        brake = min(max(-u, 0.0), 1.0) * 8.0         # 制动：主缸压力 0~8 MPa
        steer = 0.0                                  # 方向盘转角，度，左为正
        return [throttle, brake, steer]
```

`u` 为正时踩油门，为负时踩制动，两个不会同时踩。积分项限幅在 ±100，防止长时间误差让积分越积越大（积分饱和）。

### 例 2：沿车道行驶

用车道中心线 `center_rel`，瞄准前方 8 m 的点打方向盘（纯跟踪的简化版）。`controllers/path_follower.py` 是它的完整版（弯前降速、路口保护、传动比自动估计……）。

```python
"""例 2：沿车道行驶（简化版纯跟踪），定速 30 km/h。"""
import math

WHEELBASE = 2.66      # 轴距，m
STEER_RATIO = 19.0    # 方向盘转角 / 前轮转角
LOOKAHEAD = 8.0       # 前视距离，m


class Controller:
    def reset(self):
        self.integral = 0.0

    def control(self, exports, t, dt, scene):
        # ---- 纵向：定速 30 km/h ----
        v = exports["Vx"]
        err = 30.0 - v
        self.integral = min(max(self.integral + err * dt, -100.0), 100.0)
        u = 0.08 * err + 0.02 * self.integral
        throttle = min(max(u, 0.0), 1.0)
        brake = min(max(-u, 0.0), 1.0) * 8.0

        # ---- 横向：瞄准车道中心线上、离后轴 8 m 的点（纯跟踪） ----
        lane = scene["lane"]
        if lane is None:                             # 不在行车道上（停车场、开出路外）
            return [0.0, 2.0, 0.0]                   # 松油门、轻踩制动、方向盘回正
        # center_rel 的原点在前轴；纯跟踪从后轴算，所以 x 加一个轴距
        pts = [(px + WHEELBASE, py) for px, py in lane["center_rel"]]
        x, y = next(((px, py) for px, py in pts if px > 0 and math.hypot(px, py) >= LOOKAHEAD), pts[-1])
        delta = math.atan2(2.0 * WHEELBASE * y, x * x + y * y)   # 前轮转角，rad，左为正
        steer = math.degrees(delta) * STEER_RATIO                # 方向盘转角，度
        steer = min(max(steer, -540.0), 540.0)
        return [throttle, brake, steer]
```

要点：

- 目标点在车左边时 `y` 为正，算出的方向盘转角为正（向左打），符号是自然对上的。
- `next(...)` 找中心线上第一个离后轴 8 m 以上的点，找不到时用最后一个点。
- 前视距离越短跟得越紧，太短会左右摆，车速高时应该加长（完整版按车速 × 1 s 算）。

### 例 3：沿车道 + 跟车

在例 2 的基础上用 `scene["objects"]` 找前车，按“5 m + 车速 × 1.5 s”的车距减速。

```python
"""例 3：沿车道行驶 + 跟车：前面有车就按 1.5 s 车距减速。"""
import math

WHEELBASE = 2.66
STEER_RATIO = 19.0
LOOKAHEAD = 8.0
CRUISE_KMH = 40.0     # 没有前车时的车速
TIME_GAP = 1.5        # 期望车距 = 5 m + 车速 × 1.5 s


class Controller:
    def reset(self):
        self.integral = 0.0

    def control(self, exports, t, dt, scene):
        v = exports["Vx"]                            # km/h

        # ---- 找本车道正前方最近的车 ----
        # objects 已按距离从近到远排好；rel_x 前为正，rel_y 左为正，gap 是两车包围盒的间距
        front = [o for o in scene["objects"] if o["rel_x"] > 0 and abs(o["rel_y"]) < 1.8]
        target = CRUISE_KMH
        if front:
            gap = front[0]["gap"]                    # m
            want = 5.0 + TIME_GAP * v / 3.6          # 期望车距，m
            # 车距比期望小就降低目标车速（车距每差 1 m 降 3 km/h），最低 0
            target = min(CRUISE_KMH, max(0.0, v + 3.0 * (gap - want)))

        # ---- 纵向：PI 跟踪目标车速 ----
        err = target - v
        self.integral = min(max(self.integral + err * dt, -100.0), 100.0)
        u = 0.08 * err + 0.02 * self.integral
        throttle = min(max(u, 0.0), 1.0)
        brake = min(max(-u, 0.0), 1.0) * 8.0

        # ---- 横向：同例 2 ----
        lane = scene["lane"]
        if lane is None:
            return [0.0, 2.0, 0.0]
        pts = [(px + WHEELBASE, py) for px, py in lane["center_rel"]]
        x, y = next(((px, py) for px, py in pts if px > 0 and math.hypot(px, py) >= LOOKAHEAD), pts[-1])
        steer = math.degrees(math.atan2(2.0 * WHEELBASE * y, x * x + y * y)) * STEER_RATIO
        return [throttle, brake, min(max(steer, -540.0), 540.0)]
```

`abs(o["rel_y"]) < 1.8` 是“大致在本车道里”的简单判断，弯道上可以改成用中心线判断目标在不在本车道。

```python
"""例 5：拆成多个文件 + 从文件读参数。界面“算法文件”填 controllers/examples/ex5_my_algo/controller.py。"""
import json
import os

from speed import SpeedPI      # 同一个文件夹里的 speed.py，直接 import

HERE = os.path.dirname(os.path.abspath(__file__))           # 这个 .py 所在的文件夹


class Controller:
    def reset(self):
        with open(os.path.join(HERE, "params.json"), encoding="utf-8") as f:
            self.p = json.load(f)                            # {"target_kmh": 30, "brake_max": 8}
        self.speed = SpeedPI(self.p["target_kmh"])
        print("参数：", self.p)

    def control(self, exports, t, dt, scene):
        u = self.speed.step(exports["Vx"], dt)
        return [min(max(u, 0.0), 1.0), min(max(-u, 0.0), 1.0) * self.p["brake_max"], 0.0]
```

`speed.py`：

```python
class SpeedPI:
    """定速 PI：输入车速 km/h，输出 u（正 = 油门，负 = 制动）。"""

    def __init__(self, target_kmh, kp=0.08, ki=0.02):
        self.target, self.kp, self.ki, self.integral = target_kmh, kp, ki, 0.0

    def step(self, v_kmh, dt):
        err = self.target - v_kmh
        self.integral = min(max(self.integral + err * dt, -100.0), 100.0)
        return self.kp * err + self.ki * self.integral
```

`params.json`：

```json
{"target_kmh": 30, "brake_max": 8}
```

改 `params.json` 里的数字，下次点“运行”就生效，不用改代码。

## 18. 从 python_carsim_env 的写法改过来

以前直接用 python_carsim_env 时，循环是你自己写的：

```python
# 以前：自己写循环
env = CarSimEnv(sim_path)
obs = env.reset()
done = False
while not done:
    vx = obs[6]                                  # 按位置取导出变量
    action = my_algorithm(obs)
    obs, reward, done, info = env.control_step(action, inner_steps)
```

在这个平台上，**循环由平台负责**，你只保留“从数据算控制量”的部分：

```python
# 现在：平台每帧调用 control()
class Controller:
    def control(self, exports, t, dt, scene):
        vx = exports["Vx"]                       # 按名字取导出变量
        action = my_algorithm_by_name(exports)
        return action                            # [油门, 制动, 方向盘]
```

改的时候注意：

| 以前 | 现在 |
|---|---|
| `env = CarSimEnv(...)`、`env.reset()`、`env.control_step(...)` | 全部删掉，平台做 |
| `obs[6]`（按位置取） | `exports["Vx"]`（按名字取） |
| 自己算 `t`、`dt` | 用参数 `t`、`dt` |
| 自己的道路 / 路径数据 | 可以继续用，也可以改用 CARLA 的 `scene["lane"]` |
| 输出 `action` | 照旧，顺序和 .sim 导入变量一致 |

**原来的算法按位置取 `obs` 的话，不想大改**，可以把 `exports` 按原来的顺序拼回数组：

```python
NAMES = ["Xo", "Yo", "Zo", "Yaw", "Pitch", "Roll", "Vx", "Vy"]    # 按你原来 obs 的顺序写

class Controller:
    def control(self, exports, t, dt, scene):
        obs = [exports[n] for n in NAMES]        # 拼回原来的数组
        return my_algorithm(obs)                 # 原来的函数不用改
```
