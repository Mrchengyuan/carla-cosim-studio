## 1. 界面布局

布局参照车辆仿真软件（CarMaker、VTD）：中间是大的实时 3D 画面，四周停靠各个面板。

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ 菜单栏：文件 · 仿真 · 视图 · 转到 · 帮助                                         │
│ 工具栏：运行 暂停 单步 停止 │ 连接 保存 │ 地图 车辆 传感器 驾驶 CarSim 场景 采集 │ ●状态 时间 车速 实时 │
├──────────┬──────────────────────────────────────────────┬────────────────────┤
│ 工程     │ [跟车][车头][前轮][俯视][×]       主车相机 960×540 │ 属性               │
│ ▾ 开始   │                                              │ 分类 › 页面         │
│ ▾ 场景   │              实时 3D 画面（视口）              │ ┌─ 分组标题栏 ───┐  │
│ ▾ 车辆   │                                              │ │ 属性名   属性值 │  │
│ ▾ 仿真   │ ┌ 仪表 ─────────────────┐        ┌ 小地图 ─┐   │ └────────────────┘  │
│ ▾ 数据   │ │ 47 km/h  (方向盘) 油门 制动│        │ 轨迹    │   │                    │

│          │ [曲线] [车辆状态] [场景] [轨迹] [输出]           │                    │
```

- **工程树**（左）：按“开始 / 场景 / 车辆 / 仿真 / 数据”分组，点分组名可以折叠。每项右侧是当前值的摘要（地图名、车型、传感器个数、动力学来源、采集开关）。点一项，右侧“属性”面板就显示这一页的设置。“传感器套件、驾驶模式、CarSim 动力学、场景信息、测试场景、数据采集”只改配置，后端启动后就能用，没有 CARLA 也能先把一次运行准备好；“数据浏览”只要后端在运行；其余页面（地图与天气、交通流、场景对象、车辆与视角、录制与回放、实时画面）要先连上 CARLA 才能点。
- **工具栏页签**（地图 / 车辆 / 传感器 / 驾驶 / CarSim / 场景 / 采集）：按工作流程直接跳到对应页面，和点工程树一样；“地图”是“地图与天气”页，“场景”是“场景信息”页（交给控制算法的场景，和底部面板的“场景”标签一样）。
- **视口**（中）：主车相机的实时画面。生成主车后会自动打开。
  - 左上角切换视角：六个方向——后（跟车）、前、左、右、俯视、斜上方（左后方斜上），和两个特写——车头、前轮特写；窗口窄时按钮只显示图标，鼠标停在上面显示名称；× 关闭画面（节省带宽；之后的运行也不再自动打开，点“打开画面”恢复）。右上角显示相机名、分辨率、已收到的帧数。
  - **多视图**：左上角的“单画面 / 1+3 / 2×2”切换布局，多个视图同时显示。主视图是上面选的相机，其余每个视图左上角有标签，点标签选择显示内容：相机（跟车 / 车头 / 前轮 / 俯视）、语义分割、深度、实例分割（前视）、激光雷达点云（俯视）、毫米波雷达（俯视），或传感器套件里的任意相机 / 雷达（用它的实际安装位置和参数）。激光雷达按高度着色（蓝低红高），毫米波雷达按相对速度着色：红色靠近、蓝色远离、白色无相对运动（雷达测的是相对自车的速度，自车行驶时静止物体也显示为靠近），圆环间隔 10 m。
  - 左下角**仪表**：车速、仿真时间、方向盘（按实际转角旋转，下面是角度，左为正）、油门和制动条。.sim 的导入变量不是默认的 3 个（油门、制动、方向盘）时，改为显示导入 1–3 的数值。
  - 右下角**小地图**：灰点是地图上的出生点（大致就是道路），黄圈是选中的出生点，蓝线是本次运行的轨迹，白色三角是主车位置和朝向。
  - 等红灯时画面上方会提示。没有画面时，视口中间会提示下一步该做什么（连接 CARLA / 生成主车 / 打开画面），并给出按钮。
  - 分辨率、套件相机预览在“实时画面”页里设置。
- **底部面板**（中下，Ctrl+L 显示 / 隐藏）：五个页签。
  - 曲线：车速、前轮转向角（左为正）、悬架行程、油门 / 制动，四张图并排；控制算法给了 `self.debug`（见控制算法编写指南 15.5 节）时多一排，每个量一张图。
  - 车辆状态：车速 / 时间 / 实时倍率 / 帧 / 算法耗时的读数，控制输入条，位姿（CarSim 全局坐标：X Y Z、航向、俯仰、侧倾），四轮转向角（左为正）、转角、悬架表，采集进度。
  - 场景：自车 50 m 内的车辆、行人、停放车辆和前方车道（俯视图 + 表格），见第 14 节。
  - 轨迹：控制算法用 `self.draw` 画的线（例如 KMPPI 的候选轨迹），俯视：车头朝右、左为上，车道边线来自场景。横向默认自动放大到铺满这些线的范围（也可选 ×1 真实比例、×5、×10、×20），放大倍数写在图上；把底部面板拖高，放大倍数会更大。同样的线也画在 CARLA 画面里（采集数据时不画）。
  - 输出：日志和控制算法 print 的内容，见第 15 节。
- **属性**（右）：当前页面的全部设置，顶部是“分类 › 页面”和说明，下面是带标题栏的分组，每行左边是属性名、右边是值。菜单“视图 → 属性面板”可以隐藏它，让视口更大。

**面板可以自由摆放（像 Visual Studio、CarMaker 那样）**：工程、画面、属性和底部的曲线 / 车辆状态 / 场景 / 轨迹 / 输出都是独立的面板，标题就是它的页签。
- 调大小：拖面板之间的分隔条（鼠标靠近时变成蓝色）。
- 换位置：按住页签拖动，拖到别的面板上时会出现停靠提示（上 / 下 / 左 / 右 / 中间），松开就停在那里；停在中间就和那个面板叠成页签。
- 浮动：把页签拖到空处松开，面板变成浮在主窗口里的小窗，可以随意移动、调大小；再拖回停靠提示上就停靠回去。
- 关闭：面板右上角的 ×；菜单“视图”里勾选重新打开（“底部面板的页签”里可以单独开关每一个），Ctrl+L 一起显示 / 隐藏底部的五个。
- 布局自动保存（程序目录下的 `cosim_studio_layout.ini`），下次打开还是这样；菜单“视图 → 恢复默认布局”回到最初的样子。
- **分隔条**：工程树、视口、底部面板、属性面板之间的分隔线都可以用鼠标拖动调整大小。
- **状态栏**：仿真运行时变成蓝色，一眼就能看出是否在运行。
- **鼠标悬停**在带 `?` 的图标上会显示说明。
- **所有设置**（驾驶、传感器、采集、CarSim）保存在一份 JSON 配置里：Ctrl+S、工具栏“保存”，或“CarSim 动力学”页底部的“配置文件”分组。有未保存的更改时，工具栏“保存”和窗口标题带 `*`，关闭窗口或“文件 → 退出”时会问要不要保存。
- **运行中**“驾驶模式”“CarSim 动力学”“场景信息”“测试场景”“数据采集”页和传感器套件的设置不能修改：正在运行的仿真用的是开始时的配置。

## 3. 连接

**CARLA 服务器**
- 主机地址：`localhost`。CARLA 要和后端在同一台电脑上运行（本平台只按这种方式设计和测试，一键启动也只启动本机的 CARLA）。
- RPC 端口：原版 CARLA 默认 `2000`；按本项目脚本启动的改版 CARLA 是 `3000`。
- 点 **连接 CARLA**。成功后显示服务器 / 客户端版本、当前地图，以及“外部动力学接口”是否可用：
  - 绿色“改版 CARLA：可用”：一帧一次下发完整状态，速度 / IMU 读数真实，悬架动画可用。
  - 黄色“原版 CARLA：兼容模式”：画面同步效果相同，但 `get_velocity()` 等速度类读数和 IMU 陀螺仪读数为 0（加速度计为摆放位置的差分、噪声大），没有悬架动画。
  - 黄色“服务器是原版 CARLA：兼容模式”：Python 用的是改版 `carla` 包（例如 `venv_build`），但连的是原版服务器；自动用兼容模式，效果同上。
  - 蓝色“改版客户端：服务器是否改版在第一次运行时确认”：从版本号判断不出来时显示，第一次运行后变成上面两种之一。

**Python 后端**
- Python 解释器：装有 `carla` 包的 Python。写完整路径最稳妥，例如 `.../venv/bin/python` 或 `...\venv\Scripts\python.exe`。
- 桥接目录：本仓库的 `carsim_carla_bridge` 目录。程序会在自身所在目录附近自动查找。
- 后端端口：默认 `57100`，一般不用改。
- 自动启动：打开界面时自动拉起后端。
- **启动后端 / 停止后端**：手动控制。停止后端时会先清理 CARLA 里的主车、传感器和交通；这期间界面照常刷新，状态栏显示“正在停止后端”，后端几秒内没有退出就强制结束。关闭界面时也一样，等后端清理完才退出。
- **保存设置**：以上设置保存到程序目录下的 `cosim_studio_prefs.json`，下次自动加载。命令行参数（`--carla-port`、`--config`、`--light` 等）只对这一次启动有效，除非在界面上改过，否则不写进这个文件；`--tour` 自动演示不写这个文件。

**远程模式**（`cosim_studio_prefs.json` 里 `"remote_backend": true`，远程包已经设好）：后端、CARLA 和控制算法在云端服务器上运行，界面经启动器（`启动远程仿真.exe`）建立的 SSH 隧道连接本机的后端端口（远程包是 `57120`），连不上时一直自动重连（状态栏“后端 连接中”，视口显示“正在连接云端后端”）。这一栏只有后端端口和“保存设置”：界面不启动也不停止后端，关闭界面时也不停止它（SSH 断开后由服务器停止）。工具栏读数框里有蓝色“远程”标记，实时画面按 JPEG 传输。提示条上的 **重启后端** 让服务器上的后端先把各线程的调用栈记进它的日志（服务器上的 `~/.cache/carla_cosim_studio/remote_backend.log`）再退出，服务器随即启动新的后端，界面自动重新连接，并清理旧后端留在 CARLA 里的主车、交通和传感器。

> 关闭界面时，后端会自动清理 CARLA 里的主车、传感器、交通并退出；即使界面异常退出，后端检测到断开后也会自动清理。
>
> 一个后端同时只服务一个界面窗口：再开一个界面窗口连到同一个后端端口时，它会提示“这个后端已被另一个界面窗口使用”并断开，不会一直停在“正在连接”。

> **后端卡住或崩溃时**：视口上方出现红色提示条——“后端卡住了：……已经 N 秒没有完成”（一次仿真步进超过 15 秒、普通命令超过 90 秒、加载地图超过 5 分钟），或“后端进程意外退出（信号 11，段错误）”。你的控制算法 control() 超过 15 秒没有返回时，提示条写的是“控制算法 control() 已经 N 秒没有返回（my_ctrl.py 第 42 行）”：那是算法自己慢或停住了（例如 input()、断点、第一次调用时生成求解器），不是 CARLA 的问题，它返回后提示条自动消失；运行结束时的 finish() 超过 90 秒没有返回时，同样写“控制算法 finish() ……”。点提示条上的 **重启后端**：界面结束旧后端（卡住时先把它各线程的调用栈记进日志），启动新后端并重新连接 CARLA，同时把停在同步模式的 CARLA 恢复成异步、清掉旧后端留下的主车、交通、行人和传感器。上一个后端的日志保存为桥接目录的 `backend.prev.log`。
>
> **主车被 CARLA 删除时**（开出地图边界掉出了世界，或被别的程序删除）：运行会停止，提示条写明原因，画面回到“还没有主车”，重新生成主车即可。

## 4. 地图与天气

**固定世界（每次运行都一样）**：这一页最上面的卡片。勾选“每次运行前按配置重建世界”后，每次点“运行”都先：地图不对就加载配置里的地图，设好配置里的天气，清掉交通流，等世界切到同步模式后再按同一个种子重新生成同样数量的车和行人。这样同一个配置文件无论什么时候运行，周围环境都一样：交通在同步模式下按种子走同样的路线（实测两次运行，附近的车停在同一位置，误差 0 cm）。“**记下当前世界**”把现在的地图、天气和“交通流”页生成的交通（数量和种子）一次写进配置并打开开关；记得保存配置。`run.json` 的 `world` 记下这次按什么重建的。

**地图**：下拉选择 → **加载地图**（约 5–30 秒）；**重载当前地图** 恢复初始状态。加载失败时主车和交通同样已清除，界面显示 CARLA 当前所在的地图。
切换地图会清掉主车、交通和传感器。带 `_Opt` 后缀的是分层地图，可以隐藏建筑等图层，更省显存。

**天气与光照**
- 8 个快速预设：晴天正午、多云、湿滑路面、大雨、日落、夜晚、雨夜、黄昏中雨。
- “全部预设”下拉里有 CARLA 所有内置天气，选好后点“应用”。
- 9 个参数滑条：太阳高度角（负数 = 夜晚）、太阳方位角、云量、降雨、积水、路面湿度、风力、雾浓度、雾起始距离 → 点 **应用天气参数**。

**仿真设置**
- 同步模式：服务器每次 tick 才前进一帧。运行仿真时会自动切到同步，结束后恢复成这里的设置。
- 空闲时固定步长：不运行仿真时、同步模式下每帧的仿真时间，0 = 可变步长。运行仿真用“驾驶模式 → 仿真步长”，结束后恢复这里的设置。
- 关闭渲染：只算物理不渲染，速度快很多，但**相机类传感器没有图像**。
- 空闲时持续推进：同步模式且没有仿真在跑时，由后端持续 tick，否则服务器画面会停住。后端正常退出时把世界切回异步模式（之后没有程序再推进它）。
- **应用** 使设置生效（没应用的修改会一直保留，生成主车、运行结束时不会被服务器的状态冲掉，天气滑条也一样）；**刷新** 放弃没应用的修改，读取服务器当前状态。

## 5. 交通流

- 车辆数 / 行人数：0–150。
- 随机种子：同一地图、同一主车位置加同一种子 = 同样的交通布置（车型、颜色、位置，行人的位置、目的地和速度）；交通管理器之后的随机选择（路口走哪条路、变道）和行人横穿马路也按这个种子（同步模式下可重复）。不在运行中时，生成交通会让信号灯从周期起点重新开始。交通生成后就开始走动，“运行”不会重新生成交通，所以运行开始时交通走到了哪里还取决于生成后世界推进了多久。
- 只生成小汽车：不生成摩托车、自行车和卡车。
- **生成交通** / **清除交通**。交通车辆会避开主车出生点 10 m 以内的位置，由 CARLA 交通管理器驾驶（遵守信号灯、会跟车）。

## 8. 传感器套件

**预设方案**：安装位置会按当前车型的长宽高自动计算，所以要先连上 CARLA 才能加载（没连 CARLA 时其余设置照样能改）；车型没测量过时按 4.8 × 2.0 × 1.5 m 的轿车计算。

| 预设 | 组成 | 用途 |
|---|---|---|
| 单前视相机 | 1 个 RGB 相机 1280×720，挡风玻璃上方 | 车道保持、强化学习 |
| KITTI 风格 | 2 个 RGB 1242×375 双目（基线 0.54 m）+ 64 线激光雷达 + GNSS + IMU | 3D 检测、双目深度 |
| nuScenes 风格 | 6 个 RGB 1600×900 环视 + 32 线激光雷达 + 5 个毫米波雷达 | 环视感知、BEV |
| 量产车风格 | 前视主相机 / 广角 / 长焦 + 4 个侧视 + 后视 + 前向毫米波雷达 | 纯视觉方案 |
| 感知真值 | 同一位置的 RGB + 深度 + 语义 + 实例 | 分割、深度估计训练 |

**添加传感器**：相机、深度、语义、实例、激光雷达、毫米波、IMU、GNSS。

**安装位置**
- 俯视图：车头朝上，x 向前、y 向左；扇形 = 相机 / 雷达的视场角，圆环 = 激光雷达；蓝色十字是 CarSim 参考点（坐标原点）。
- 侧视图：车头朝右，z 向上；扇形 = 相机的垂直视场角（含俯仰）。
- **按住传感器圆点拖动**即可改位置，网格间距 1 m。安装位置用 CarSim 车身坐标系：原点在 CarSim 参考点（默认前轴中心的地面），x 向前、y 向左（左为正）、z 向上；航向左为正（90 = 朝左），俯仰正 = 低头。打开旧版本保存的配置时，连接 CARLA 后会自动换算；换算前安装位置不能修改。

**传感器列表**：勾选框启用 / 停用；点名称选中；最右一列是这个传感器每帧大约多少 MB。

**属性分组**（选中传感器后出现）
- 名称（也是输出文件夹名）；x / y / z、航向（0 朝前、90 朝左、-90 朝右、180 朝后，左为正）、俯仰（正数 = 向下看）、侧倾：可以拖动数值，也可以双击直接输入。
- 相机：分辨率预设（640×360 到 2560×1440，以及 KITTI 的 1242×375）、宽、高、水平视场角。
- 激光雷达：线数 16 / 32 / 64 / 128、量程、每秒点数、上下视场角。采集时每帧自动输出完整一圈扫描，所以每圈发射的激光束数 = 每秒点数 × 仿真步长（例如 130 万 × 0.02 s = 2.6 万束，只有真实 10 Hz 雷达一圈的 1/5；要一样密，把每秒点数设成“每圈束数 ÷ 仿真步长”，CARLA 会更慢）。保存的点比束数少：没打到东西的激光束没有点，CARLA 默认还随机丢掉约 45%（`dropoff_general_rate`），远处反射强度低的点再丢一小部分。
- 毫米波雷达：水平 / 垂直视场角、量程、每秒点数。
- **预览这个相机**：用它的实际安装位置和视场角，在“实时画面”里看它拍到什么（需要先生成主车）。
- **复制 / 删除**。

**数据量估算**：每帧 MB、写盘速率 MB/s、每小时 GB、本次最多 GB，以及和磁盘剩余空间的对比条。输出目录所在的盘或网络共享不存在（例如拔掉的移动硬盘）时显示红色提示，采集拒绝开始。

## 9. 驾驶模式

**车辆动力学由谁计算**
- **CarSim 联合仿真**：你的控制算法控制 CarSim 的车，CarSim 计算动力学；CARLA 每帧把车放到 CarSim 算出的位置和姿态（车轮转角、转速、悬架也照 CarSim），自己不算动力学，只负责场景、交通、传感器和画面。
- **CARLA 物理**：用 CARLA 自带的 PhysX 车辆模型，不需要 CarSim。

**控制算法（CarSim 联合仿真）**

默认就是“**我的控制算法**”：每帧把 CarSim 的全部导出变量交给你的 Python 算法，算法返回的油门、制动、方向盘送回 CarSim（.sim 里的 REPLACE 导入变量）。

- **算法参数**：算法文件开头的大写常数（`NAME = 数字 / 文字 / True / False`，行尾注释是说明），直接在这里改，改过的显示成蓝色；运行时写回模块里的同名常数（文件本身不改），输出窗口和 `run.json` 记下改了哪些；🔄 在改了文件后重新读取，“全部恢复”回到文件里的值。详见控制算法编写指南第 13 节。
- **干扰（检验算法的鲁棒性）**：勾选“开启干扰”后，每次运行在你的算法和平台之间加上：执行器延迟（算法的输出晚这么久才到 CarSim）、测量延迟（算法拿到的导出变量和场景是这么久以前的）、导出变量的高斯噪声（每个变量一个标准差，单位同导出变量）、车道信息丢失概率（这一帧 `scene["lane"]` 为 None）。延迟按帧取整，最长 1 s；同样的设置和随机种子每次运行完全一样。“典型设置”一键填上执行器延迟 0.1 s、测量延迟 0.05 s、车道信息丢失 5%，以及 Vx / Vy / AVz / Yaw 常见传感器量级的噪声。运行记录（`log.csv`）记的还是 CarSim 的真值；开始时输出窗口说明开了哪些，`run.json` 的 `disturb` 记下设置。只作用在自己的控制算法上（测试用驾驶方式和 CARLA 物理下不用）。
- **算法文件 .py**：你的算法文件。相对路径以 `carsim_carla_bridge` 目录为准，也可以填绝对路径；输入框下方显示实际使用的绝对路径，✓ = 找到，✗ = 找不到或未设置。**每次点“运行”都会重新加载**（连同它从同一目录和子目录 import 的文件），改完代码直接再点运行，不用重启界面。远程模式（见第 3 节）下算法文件在云端服务器上：✓ / ✗ 由服务器上的后端检查，显示服务器上的绝对路径（相对路径以服务器上的 `carsim_carla_bridge` 目录为准）。
- **浏览…**：输入框右边的文件夹图标。本机模式打开系统的选择文件对话框（Windows 自带的对话框；Ubuntu 上用 zenity）；远程模式打开“选择控制算法（云服务器上的文件）”窗口，列出服务器上的文件夹和 `.py` 文件：点文件夹进入，“上一级”返回，“controllers”回到算法文件夹；每个文件显示它开头说明的第一行和找到的入口（带 `control()` 方法的类、`control` 函数），有语法错误的标红。点文件选中，再点“选择”（或双击文件），路径和入口自动填好；文件里有几个入口时在窗口下方选。选择时只读取文件内容，不会运行它。
- **入口**：文件里的类名（默认 `Controller`）或函数名。用“浏览…”选文件时自动填好。

```python
# 例：C:\carla-cosim-studio\carsim_carla_bridge\controllers\my_controller.py
class Controller:
    def reset(self):                       # 可选，每次运行开始调用一次
        self.integral = 0.0

    def control(self, exports, t, dt):     # 每帧调用一次
        vx = exports["Vx"]                 # 按变量名取 CarSim 导出变量（CarSim 单位）
        ...                                # 你的算法
        return [throttle, brake, steer_sw] # 按 .sim 里导入变量的顺序

    def finish(self, reason):              # 可选，每次运行结束调用一次
        ...                                # 例如保存自己的日志；reason = 结束原因
```

- `finish(reason)`：可选。运行结束时（到时、碰撞停止、点了停止、出错）调用一次，`reason` 是和输出窗口里相同的结束原因，例如“达到设定的运行时长 20 s”“碰撞：撞到 vehicle.audi.tt（id 42）”“运行被停止”。入口是函数时，写模块级的 `finish(reason)` 函数。`finish` 里出错只在输出窗口提示，不影响收尾。
- `exports`：字典，键是“CarSim 动力学”页导出变量列表里的名字，值是 CarSim 单位，跟随“CarSim 动力学”页的单位设置（默认 `Vx` km/h、`Yaw` deg ……；当前单位在 `scene["units"]` 里）。
- `t`：CarSim 当前时间（s）；`dt`：控制周期 = “仿真步长”。
- 返回值：按 .sim 里导入变量的顺序。python_carsim_env 默认是 `[油门 0~1, 制动, 方向盘转角 deg（左正）]`。
- 算法里可以 `import` 同目录的其他文件，也可以直接 `import` python_carsim_env 里的模块。算法 import 的自己的文件不要和后端或 Python 已经加载的模块同名（例如 `config.py`、`settings.py`、`scene.py`），否则运行前会提示改名（同目录里算法用不到的脚本不受影响）。
- 出错时（文件不存在、入口名不对、算法抛异常）运行会停止，原因显示在视口上方的提示条里，底部“输出”页会自动打开：指出出错的文件和行号（错在 import 的辅助文件里时，也指出是算法文件哪一行调用的）；入口名不对时列出文件里可用的类和函数；取了“场景信息”页没勾选的量时提示去那里勾选。
- 算法里 `print()` 的内容（写到 `sys.stderr` 的、`logging`、Python 的警告也一样）显示在底部“输出”页，点“算法”只看这些；加载时（模块顶层、`reset()`）、每次 `control()` 和运行结束时 `finish()` 里输出的都有。每秒最多显示 20 行，多出的合成一行“（省略 N 行，全部输出见 backend.log）”；`carsim_carla_bridge/backend.log` 里有全部内容。算法出错时，“算法”里还会列出出错位置：只列你自己文件里的调用栈（外层在前，每行是文件、行号、函数和那一行代码），最后一行是异常。
- 自己写算法：见 [控制算法编写指南](控制算法编写指南.md)。
- 自带五个示例：`controllers/example_controller.py`（PI 定速 + 蛇形转向，拿来改）；`controllers/path_follower.py`（路径跟踪：纯跟踪沿 CARLA 的车道中心线行驶，弯前降速，路口不跟错车道；改文件开头的轴距、目标车速、制动量程即可用于你的 CarSim 车辆，见[远程使用指南第 5 节](远程使用指南.md#5-示例控制算法路径跟踪controllerspath_followerpy)）；`controllers/scene_controller.py`（用场景信息：沿车道行驶，前方有车或行人就跟车 / 停车）；`controllers/lane_change_avoid.py`（避障：在 path_follower 的基础上，本车道被锥桶、护栏、停着的车挡住就换道绕过去，过去后换回原车道；左右都换不了就减速停车；要在“场景信息”页车道里加勾 `left_lane`、`right_lane`，和 path_follower.py 放在同一个文件夹）；`controllers/simple_path_follower.py`（把你项目里的 SimplePathFollower 接进来，需要导出 `LatErr`）。

**用 CARLA 场景里的信息（周围的车辆、行人，前方车道，传感器数据）**

算法本来就在 Python 后端里运行，后端每帧从 CARLA 读出周围的车和人、车道，直接交给算法，不经过界面。把 `control` 写成 4 个参数就会收到 `scene`（一个字典）：

```python
    def control(self, exports, t, dt, scene):
        for o in scene["objects"]:            # 自车 50 m 内的车辆和行人，由近到远
            o["id"], o["type"]                # 编号（整次运行不变）、"vehicle" / "walker"
            o["rel_x"], o["rel_y"]            # 相对位置，自车坐标系（x 向前、y 向左），m
            o["rel_vx"], o["rel_vy"]          # 相对速度，km/h（rel_vx 为负 = 在靠近）
            o["dist"], o["gap"]               # 中心距离、包围盒间距，m
        lane = scene.get("lane")              # 勾选了车道量时才有：width、offset、heading_err、center_rel ...
        ego = scene["ego"]                    # ego["X"]、ego["Y"]、ego["Yaw"] 就是 CarSim 的 Xo、Yo、Yaw
        return [throttle, brake, steer_sw]
```

一切按 CarSim：全局坐标系就是 CarSim 的全局坐标系（原点在出生点），自车坐标系原点在 CarSim 参考点，x 向前、y 向左（**左为正**）；速度、角度用 CarSim 的导出单位（默认 km/h、deg）。每个量的完整定义见 [场景与数据接口说明](场景与数据接口.md)。只写 3 个参数的算法照旧运行。

| 施工封道 | “运行时摆放封道”开关；4 个预设（点一下替换下表）：**封闭本车道（锥桶）**、**封闭左侧车道（护栏）**、**连续两处封道**（250 m 封本车道、550 m 封左侧车道）、**只剩一条车道**（300 m 封本车道和右侧两条）。表里每一处可改：**距离**（从出生点沿道路算，m；经过路口时走转弯最小的分支）、**车道**（相对出生时所在的车道：本车道、左侧 / 右侧第 1~3 条，只算同方向的车道）、**渐变段**（锥桶 / 护栏斜着把车道收窄的长度，m）、**封闭长度**（m）、**类型**（锥桶 / 护栏），右边的垃圾桶删除这一处；“添加一处封道”接在最后一处后面 100 m |
| 在控制算法里 | 锥桶、护栏和导向牌作为 `type = "static"` 的障碍物出现在 `scene["objects"]` 里（要在“场景信息”页障碍物里勾选“施工锥桶 / 护栏”，默认已勾；没勾时这里有“勾选”按钮） |

- 一处封道 = 渐变段（本车道和右侧车道从右往左收窄，左侧车道从左往右收窄）+ 封闭段（两侧有可行驶车道的边各摆一排）+ 渐变段后面一块箭头导向牌。锥桶渐变段每 3 m 一个、封闭段每 6 m 一个；护栏首尾相接。
- 摆不下时（那里没有这条车道、路在那之前就断了、数值超出范围）运行不会开始，提示说明原因，CARLA 里什么都不会摆。
- 锥桶和护栏是静态物体：CarSim 的车撞上不会把它们推走，按“场景信息”页的碰撞设置记录或停止运行。运行结束后它们留在原地，下一次运行开始、换地图、重新连接或后端退出时删除；后端崩溃或被杀掉后，“重启后端”会把留下的删掉。
- 运行记录的 `run.json` 里 `scenario` 记下这次摆了哪些封道、每处多少个物体。
- 例：`controllers/lane_change_avoid.py` 是避障示例：本车道被封就换道绕开，过了封道换回原车道，左右都封死就减速停车（要在“场景信息”页车道里加勾 `left_lane`、`right_lane`）；`controllers/path_follower.py` 只跟车道、不避障，开进封闭的本车道会撞上锥桶，可以用来检查碰撞检测。自己写避障算法时看 `type == "static"` 的目标的 `rel_x`、`rel_y`、`gap`。

**测试用驾驶方式**（折叠栏，还没有算法时检查链路用，平时不用管）

| 方式 | 说明 |
|---|---|
| 演示（开环） | 固定的加速 + 蛇形 + 制动，看 CARLA 的车是否跟着 CarSim 动、转向方向对不对 |
| 路线跟随 | 程序在 CARLA 路网上规划路线，算出油门、方向盘送给 CarSim；可设目标车速、目的地出生点 |
| 键盘驾驶 | W / ↑ 油门，S / ↓ 制动，A、D / ←、→ 转向，手动开 CarSim 的车 |

路线跟随和键盘驾驶下有“制动输入比例”：0–1 的制动指令乘以这个系数再送给 CarSim，CarSim 制动输入是主缸压力（MPa）时设 10 左右。

**驾驶方式（CARLA 物理）**：路线跟随、CARLA 自动驾驶（交通管理器：遵守信号灯、跟车、变道；可设相对限速 %、忽略红绿灯）、键盘驾驶。

**运行设置**
- 仿真步长：CARLA 每帧的仿真时间，最大 0.1 s（CARLA 的物理每帧最多算 0.1 s）。CarSim 每帧内部积分 `步长 / t_step` 步，**最好是 t_step 的整数倍**（例如 t_step = 0.001 时用 0.02）；不是整数倍时，运行开始会自动对齐到最近的整数倍（日志里提示实际步长），CARLA 的帧长和交给控制算法的 dt 都用对齐后的值。控制算法文件开头写了 `FRAME_DT = 0.05` 这样一行时（例如 KMPPI），运行用算法要的步长，输出窗口会说明（见控制算法编写指南第 5 节）。
- 运行时长：默认 0 = 一直运行，直到点“停止”；用真实 CarSim 时最晚在 .sim 的结束时间（TSTOP）结束，运行开始时日志里会写出这个时间，这一栏下方也显示上次运行的结束时间和实际步长。设了时长（例如 20 s），到时会自动结束并让主车停车，画面上方会出现黄色提示条说明原因；所以如果看到车在绿灯前不走、工具栏显示“已完成”，就是运行时长到了。
- 运行记录目录（默认 `runs`）：每次运行在这里新建一个文件夹 `年月日_时分秒_算法文件名`，不覆盖以前的记录；输入框下方显示最近一次运行的文件夹，运行结束时输出窗口也写出文件夹和运行指标（车道偏移 RMS / 最大、航向偏差最大、不在车道上的时间、碰撞次数和第一次的时刻、前方最小间距、最小 TTC、最大加速 / 减速度和 jerk、行驶距离、有 `Ay` 导出时的最大 |Ay|），以及按通过标准的判定（见第 17 节）。文件夹里：`log.csv` 按采样周期（“数据采集”页设置，从运行开始时刻（CarSim 的 t_start，一般为 0）算起）记录“场景信息”页勾选的自车量（列名 `ego_X` 等）、CarSim 导出变量和控制算法的输出 `u1` … `un`（第一行为空），`log_objects.csv`（障碍物，每行一个）、`log_lane.csv`（车道），`config.json`（这次的配置）、算法文件的副本、`run.json`（地图、出生点、交通流种子、CARLA 接口、.sim 文件、开始 / 结束时刻、结束原因、运行指标），详见[场景与数据接口说明](场景与数据接口.md) 5.2。旧配置里填的 `cosim_log.csv`：文件夹建在它所在的目录，文件名沿用 `cosim_log`。留空 = 不记录。磁盘剩余不到 10 GB 时停止写记录（仿真继续）。检查同步：`ego_X / ego_Y / ego_Yaw`（车在 CARLA 里实际的位置，换算到 CarSim 坐标）应该和 `Xo / Yo / Yaw` 一致。

- 运行记录的路径和单位：相对路径以 `carsim_carla_bridge` 目录为准。CSV 里不写单位：`ego_` 列、障碍物和车道的量用“CarSim 动力学”页设置的单位；CarSim 导出变量列和 `u1` … `un` 是 CarSim 原样的数值，单位就是 .sim 里导出、导入变量的单位（页上的单位要和 .sim 一致，但这些列不经换算）。

> 键盘驾驶时，界面窗口需要有焦点，并且光标不能停在输入框里。

**测试场景页的动态目标**（“仿真 → 测试场景”，施工封道下面的卡片）：会动的车和行人，和封道一样相对出生点摆放、每次运行完全一样（每帧按车道精确摆放，不走 CARLA 物理）。
- 4 个预设：**前车慢行**（前方 80 m 本车道 40 km/h 匀速）、**前车急刹**（前方 60 m、60 km/h，你跟近到 40 m 时以 6 m/s² 刹停）、**旁车切入**（左侧车道前方 40 m、50 km/h，你靠近到 25 m 时用 2.5 s 并进你的车道）、**行人横穿**（前方 120 m 路右侧，你靠近到 45 m 时以 5 km/h 横穿）。
- 表格里每一个都能改：类型、距离（从出生点沿道路）、车道（前车急刹固定在本车道；行人按左 / 右决定从哪一侧出发）、速度、触发距离（你的车离它这么近时开始动作）、参数（前车急刹是减速度 m/s²，旁车切入是切入用时 s）；“添加一个动态目标”、垃圾桶删除。
- “运行时摆放封道”同时控制封道和动态目标。它们在算法里就是 `scene["objects"]` 里的车和行人，速度是真实值（原版 CARLA 读不出被摆放物体的速度，平台直接给出）；撞上照常判碰撞；`run.json` 的 `scenario.actors` 记下摆了哪些。摆不下（那里没有这条车道、路太短）时运行不会开始，并说明原因。

## 10. CarSim 动力学

**CarSim 模型**
- 模拟 CarSim：没有 CarSim 许可证时勾选，用内置的简单车辆模型测试整条链路。勾选后工具栏读数框显示黄色“模拟 CarSim”，
  左侧“CarSim 动力学”旁显示“模拟”，运行开始的日志里也会注明，不会和真实 CarSim 的结果混淆。
- 初始车速 m/s（勾选“模拟 CarSim”时出现）：模拟 CarSim 在 t = 0 时的车速，像 .sim 里的初始车速；默认 0，从静止起步。
- Chrono 宝马（服务器）：没有 CarSim 时，用后端所在电脑上的 PyChrono 宝马 E90 多体整车模型代替（和“模拟 CarSim”二选一）。
  后端运行时自己在 conda 环境 `chrono` 里启动它，不用开终端；它的导入量是 `[纵向加速度 m/s², 前轮转角 rad]`，配 KMPPI 算法用
  （`controllers/kmppi/controller.py`）。勾选后多一行“初始车速 m/s”（默认 20）：车先以这个速度直线稳定 1 s，再从出生点开始。
  左侧“CarSim 动力学”旁显示“Chrono”，运行开始的日志写“（Chrono 宝马 E90 代替 CarSim）”。启动失败时（比如没有 chrono 环境）运行不会开始，
  并说明原因；它的输出在 `carsim_carla_bridge/chrono_service.log`。
- `.sim` 文件：CarSim 生成的仿真文件（Windows 上一般在 CarSim 数据库目录下）。
- python_carsim_env 目录：CarSim 的 Python 接口所在目录。一般不用填：填的目录里没有 `carsim_env.py` 时，从 `.sim` 所在的文件夹往上逐级找，找到就用（下方注明“自动找到”）。
- **检查 .sim**（“CarSim 模型”卡片底部）：运行前把 CarSim 试启动一次（和运行时同一条路：本机 CarSim、远程的 CarSim 服务、Chrono 宝马或模拟 CarSim，不需要 CARLA），逐项列出结果（✓ 正常、⚠ 提醒、✗ 错误）：CarSim 能否启动（.sim、求解器、许可证）；导出变量个数是否等于本页列表的个数，必需的导出变量是否都在；导入变量个数（测试用驾驶方式要 3 个，自己的算法要按这个个数返回）；t_step 能否整除仿真步长（算法写了 FRAME_DT 时按它）；运行时长是否超过 .sim 的结束时间；初始车速（算法参数里有 `REF_SPEED` 时，例如 KMPPI，初始车速离它太远会提醒）；t = 0 的导出变量是否可信（NaN、俯仰 / 侧倾超过 10°、左右前轮转角不一致，多半是顺序或单位错了）。试启动后 CarSim 马上关闭。
- 两个输入框右边的文件夹图标是“浏览…”：打开系统的选择框（Windows 自带的对话框；Ubuntu 上用 zenity）选文件 / 文件夹，填入完整路径。
- 这两个输入框下方显示实际使用的绝对路径（相对路径以 `carsim_carla_bridge` 目录为准）：✓ = 找到，✗ = 找不到或未设置。
- 远程模式（见第 3 节）下，真实 CarSim 在这台 Windows 电脑上的 CarSim 服务里运行：`.sim` 文件和 python_carsim_env 目录是这台电脑上的路径（输入框下方注明“（这台 Windows 电脑上的路径）”），✓ / ✗ 也在这台电脑上检查。页面上显示“Windows 上的 CarSim 服务：已连接（电脑名）”，或红色的“未连接 — 请双击启动脚本”（连接 CARLA 之后才显示，停在这一页时每 2 秒左右更新）。勾选“模拟 CarSim”时不需要 CarSim 服务，简单车辆模型在服务器上运行。
- 点“运行”时先检查设置和文件（仿真步长、驾驶方式、算法文件、`.sim`、python_carsim_env、`.sim` 指向的 CarSim 求解器），
  有问题直接报出原因，主车不会被重新生成。CarSim 读 `.sim` 失败（许可证、数据文件路径等）时显示 CarSim 自己的报错。
- CarSim 的初始位置（t = 0 的 Xo、Yo、Yaw）不在原点时，车会从离出生点相应距离处出发、车头方向与出生点方向差相应角度，日志里有警告。
- CarSim 在 `.sim` 的结束时间之前自己停下（`.sim` 里的事件 / 停止条件）时，结束原因写“CarSim 模型请求停止”和当时的时间。

**导出变量（顺序必须与 .sim 一致）**
- 绿色提示 = 必需变量齐全；红色提示 = 缺少哪些变量。蓝色变量名 = 必需变量。
- ↑ ↓ 调整顺序，✕ 删除，在输入框里写名字再点“添加”可追加一个。
- 从 CarSim 的 Export 列表复制，粘贴到文本框，点 **用粘贴内容替换**（空格、换行、逗号都能作分隔符）。
- **补全推荐变量**：追加速度、角速度、四轮转速、悬架行程等推荐变量（CarSim 里也要按同样顺序加上）。
- 每个变量的含义见 [CarSim 导出变量清单](../carsim_carla_bridge/docs/CarSim导出变量清单.md)。
- 运行时只能核对个数；顺序或单位不对不会报错，但位姿、交给算法和写进记录的值都会错。所以运行开始时和车开起来后（约 1 s）会检查导出值像不像对应的变量：`Zo` 约为参考点离地高度（高度模式“贴合 CARLA 路面”时不查）、`Pitch` / `Roll` 小于 10°、左右前轮转角同号且大小相近、`Vx` 和各车轮转速与 `Xo` / `Yo` 的变化对得上。不像时输出里给黄色提示“导出变量可疑：……”，运行照常进行。这只能发现一部分错误：速度、车轮转速的单位设错能发现；角度单位只有读出的角度明显过大时（页上 rad、.sim 输出 deg）才能发现，反过来（页上 deg、.sim 输出 rad）发现不了；角速度、悬架行程的单位，`Pitch` / `Roll` 互换、左右前轮互换也发现不了。所以仍要按 .sim 核对一遍。

**单位与坐标**
- 角度、速度、角速度、车轮转速、悬架行程的单位（默认是 CarSim 用户单位：deg、km/h、deg/s、rpm、mm）。“模拟 CarSim”也按这里的单位输出。
- 高度模式：使用 CarSim 高度 / 贴合 CARLA 路面（CarSim 路面和 CARLA 地图高度不一致时用后者）。
- 参考点在前轴中心：CarSim 的 Xo / Yo / Zo 默认在前轴中心的地面处；不是的话取消勾选并填写参考点位置（相对车身中心的地面，x 向前、y 向左、z 向上）。传感器安装位置和场景信息都以参考点为原点，改了参考点，传感器在车上的实际位置也跟着移动。
- CARLA 接口：自动 / 强制改版接口 / 强制原版兼容。
- 方向盘满量程：方向盘转这么多度，对应 steer = ±1。

**配置文件**：载入 / 保存 / 恢复默认。相对路径和界面里其他路径一样，以桥接目录 `carsim_carla_bridge` 为准（默认存为 `carsim_carla_bridge/cosim_config.json`），输出里会显示完整路径；下次打开界面时自动载入上次保存的配置，文件找不到时会提示。卡片下面列出**最近打开**的配置（最多 5 个，菜单“文件 → 最近打开”里是 8 个），点一下就载入；文件已经不在的会提示并从列表里去掉。

**从模板新建**（菜单“文件 → 从模板新建”）：

| 模板 | 内容 |
|---|---|
| 空白工程 | 全部默认设置 |
| KMPPI 路径跟踪（Chrono 宝马，Town04 高速） | 算法 `controllers/kmppi/controller.py`，动力学用 Chrono 宝马 E90（初始 20 m/s），跑 40 s；随后自动切到 Town04 高速起点 |
| 施工封道避障测试（Town04 高速） | 保留当前的算法文件和参数，前方 250 m 锥桶封闭本车道，撞上停止运行，跑 40 s；随后切到 Town04 高速起点 |
| 数据集采集（nuScenes 传感器，CARLA 自动驾驶） | CARLA 物理 + 自动驾驶，nuScenes 传感器，固定世界（Town10、30 辆车 20 个行人），10 Hz 采集最多 200 帧 |

新建前会确认（有未保存的更改时提醒）。CARLA 地址、车型、出生点、CarSim 的 .sim / python_carsim_env 路径、导出变量和单位、车辆参数辨识的输入都保留；新配置存成单独的文件（例如 `kmppi_chrono.json`，已有同名文件时加 `_2`），当前打开的文件不动，按 Ctrl+S 保存。
- 载入：文件里没写的部分用默认值（和命令行一样），不会沿用之前那份配置；文件里的车型同时在车型列表里选中。
- 保存：同时写入当前连接的 CARLA 主机和端口。先写临时文件再替换，写不进去时原文件不变，输出里报错。
- 恢复默认：先确认；除车型和出生点外，所有页面的设置都恢复为默认值，点“保存”才写入文件。运行中不能载入或恢复默认。

## 11. 数据采集

1. 在“传感器套件”页配好传感器。
2. 在本页打开 **运行时采集数据**。打开时如果采样周期短于 0.05 s，会自动设成约 0.1 s（10 Hz），仿真步长不变。运行记录 CSV 也用这个周期，关掉采集后不会改回（要每帧记录，把采样周期改回仿真步长）。
3. 设置输出目录、场景名称（留空 = 按时间自动命名）。
4. **采集内容与格式**
   - 采样周期（s）：按仿真步长的整数倍执行，从运行开始时刻（CarSim 的 t_start，一般为 0）算起（页面上显示“每几帧一次、多少 Hz”；改仿真步长时采样周期保持不变，不是整数倍时会提示实际周期）。传感器、CarSim 变量、障碍物、车道在同一帧同时采样；运行记录也用这个周期；两次采样之间发生的碰撞 / 压线事件记在下一个采样帧里。控制算法仍然每帧调用。KITTI、nuScenes 等数据集一般用 10 Hz。
   - RGB 格式：JPG（大小约为 PNG 的 1/4）或 PNG（无损）；JPG 质量 50–100。语义 / 实例图是无损 PNG，深度是以米为单位的 `.npy`。
   - 点云格式：`.bin`（float32 x, y, z, 强度，x 前 y 左）或 `.npy`。
   - 真值标注：保存范围内车辆、行人和地图里停放的汽车、卡车、公交车的 3D 框、类别、ID、速度。
5. **停止条件（至少设一项）**：最多帧数、最长时间（真实时间）、最大容量 GB。磁盘剩余少于 10 GB 时也会自动停止。

## 12. 录制与回放

- **开始录制 / 停止录制**：CARLA 录制器会记录整个场景（所有车辆、行人、信号灯），文件保存在 **CARLA 服务器所在的机器**上。录制器在 CARLA 服务器里运行，所以后端退出、重启或重新连接时会自动停止录制（否则会一直写到 CARLA 退出）；换地图和开始回放也会结束录制。“录制中”标记以后端报告的状态为准。
- **回放**：可设起始时间、时长（0 = 全部）、相机跟随的对象 ID；运行中不能回放（先停止运行）。回放会把录像里的主车、交通车和行人重新生成一遍，所以回放前会先清掉当前的主车和交通（否则两份叠在一起会互相弹飞）；视口跟随录像里的主车。之后生成主车、点“运行”或生成交通时，回放留下的车辆会被自动清掉。
- **文件信息**：显示录制文件里的帧数、对象等。
- 用法举例：先录一段场景，之后换一套传感器，在回放时重新采集，不用重跑仿真。

## 13. 实时画面

- 视角：后方（跟车）、前方、左侧、右侧、俯视、斜上方六个方向，加车头和前轮特写（看转向、车轮转动、悬架跳动最清楚）。前、左、右、斜上方与车的距离按车的大小自动调整。多视图里每个视图的“相机 · …”选项也是这 8 个。
- 套件相机：用传感器套件里某个 RGB 相机的实际位置和视场角来预览。
- 分辨率：480×270 到 1280×720，默认 960×540。分辨率越高画面越清楚，但传给界面的数据量越大。
- **多视图**：布局（单画面 / 1 大 + 3 小 / 2 × 2），以及视图 1–3 各自显示什么（同视口标签里的选项）。2 × 2 时每个视图 640×360，1+3 时小视图 480×270；视图越多，CARLA 渲染和传输越重。
- **打开画面 / 关闭画面**。画面显示在中间的视口里；生成主车后会自动打开。“关闭画面”和视口左上角的 × 一样，之后的运行也不再自动打开，点“打开画面”恢复。

## 14. 视口仪表与底部面板

- 视口左下角仪表：车速、仿真时间、方向盘（按实际转角旋转，角度左为正）、油门和制动条；右下角小地图显示出生点、本次轨迹和主车朝向；等红灯时画面上方会提示“正在等红灯”。
- 底部面板“车辆状态”页签：
  - 车速、仿真时间、实时倍率、帧。
  - 算法耗时（本帧 / 最长，ms）：你的 `control()` 每次调用花的时间，不含 CarSim、CARLA 和准备 `scene` 的时间；比仿真步长长时仿真就跑不到实时。只在用“我的控制算法”的 CarSim 联合仿真时有；运行结束时“输出”页给出调用次数、平均和最长值。
  - 油门、制动、转向条（转向 = 方向盘转角 / 最大转角，居中为 0，左为正，向左打方向时条向左伸）。制动的单位由 .sim 决定（例如制动压力 MPa），制动条按本次运行出现过的最大值缩放（至少到 1），右边的数字是原值。
  - .sim 的导入变量不是默认的 3 个（油门、制动、方向盘）时，这里、仪表和“曲线”页改为显示导入 1–3（`control()` 返回的前 3 个值，按 .sim 的导入顺序），刻度按本次运行的数值自动缩放。
  - 位姿：CarSim 全局坐标系（原点 = 出生点，x 沿出生点方向，y 向左），就是 CarSim 参考点的 X、Y、Z 和航向、俯仰、侧倾，和导出变量 Xo、Yo、Yaw 对应，也和“场景”页签一致；航向左为正，俯仰正 = 低头，侧倾正 = 右侧下沉，角度单位按“CarSim 动力学”页。
  - 四轮表：转向角（左为正，和 CarSim 的 Steer_L1 / Steer_R1 同号）、转角（车轮自转的累计角度）、悬架行程（压缩为正）。
  - 采集进度（采集时显示）。
- 底部面板“曲线”页签：车速、左右前轮转向角（左为正）、四轮悬架行程、油门 / 制动（纵轴随数值自动缩放）。鼠标滚轮缩放，拖动平移，双击恢复。
- 底部面板“场景”页签：自车 50 m 内的车辆、行人、停放车辆和前方车道，按 CarSim 坐标和单位显示（显示全部量，不受“场景信息”页勾选的影响）。左边是俯视图（x 向前朝上、y 向左，圆环间隔 10 m，蓝点 = 参考点；蓝色车辆、橙色行人、灰色停放车辆、黄线是车道中心，发生碰撞的目标标红），右边是表格（id、类型、车型、rel_x / rel_y、dist、gap、相对速度、速度），上方一行是车道宽、偏离量、限速、红绿灯。勾选“隐藏停放车辆”只看行驶的车和人；鼠标移到表格某一行，俯视图里对应的框会高亮。运行结束后保留最后一帧，方便查看撞到了什么。

## 16. 数据浏览与导出

工程树“数据 → 数据浏览”。选中这一页时，中间的视口显示数据集（不是实时画面）。

**浏览**
- 右侧“数据集”列表列出“数据采集”页输出目录下的所有采集（名称、帧数、大小），点一行打开；每次打开这一页（以及停在这一页时一次运行结束）都会重新列出，🔄 手动刷新，🗑 删除（会再确认一次；只能删采集生成的目录）。浏览、播放和删除由后端的单独线程处理，运行中使用也不会拖慢仿真。
- 视口左边是相机类视图（相机 / 语义 / 深度 / 实例），右边是激光雷达或毫米波雷达俯视图；点视图左上角的标签换成数据集里的其他传感器。
- 勾选“显示真值框”时，相机图上画出每个目标的 3D 框（按类别着色：车蓝、卡车/公交橙、两轮紫、行人红，并标出 ID），俯视图上画出框的轮廓和车头方向。
- 视口底部的播放条：首帧 / 上一帧 / 播放 / 下一帧 / 末帧，拖动条跳到任意帧；右侧显示序号、帧号、仿真时间、车速。鼠标在视口上时 ← → 逐帧，空格播放 / 暂停；“播放速度”设每秒几帧。
- “当前帧目标”表列出这一帧的真值目标：ID、类别、距离、框内激光点数（0 表示激光雷达看不到，多半被遮挡或太远）。

**导出**
- **KITTI**（3D 目标检测常用）：选一个 RGB 相机作为 `image_2`、一个激光雷达作为 `velodyne`；“最少激光点”以下的目标不写进 `label_2`。输出 `training/{image_2, velodyne, calib, label_2}` 和 `ImageSets/`，另附 `carla_frames.txt`（KITTI 序号 ↔ CARLA 帧号）。套件里如果有一台和所选相机内参、朝向相同、在它右侧的 RGB 相机（例如 KITTI 预设的 `cam_right`），就作为双目右相机导出到 `image_3`，`P3` 里带上实际基线。图像按 KITTI 惯例存成 PNG（比 JPG 大约 4 倍）；点云的 y 轴已翻转成 KITTI 的右手约定；`occluded` 由框内激光点数估计。
- **nuScenes**：全部 RGB 相机、激光雷达、毫米波雷达（通道名 = 传感器名大写，如 `CAM_FRONT`、`LIDAR_TOP`），一个采集 = 一个 scene，目标带实例跟踪（前后帧关联）、属性、可见度（由激光点数估计）、`num_lidar_pts / num_radar_pts`。用官方工具读取：`NuScenes(version='v1.0-carla', dataroot='<输出目录>')`。
- 输出目录默认在数据集旁边（`<数据集>_kitti` / `<数据集>_nuscenes`），必须是空目录或不存在；导出前会估算大小，磁盘剩余空间不足（保留 10 GB）时拒绝。导出在后台进行，显示进度。

**坐标约定**（导出时自动转换，已用 CARLA 语义激光雷达和 nuScenes 官方工具验证）：CARLA 是左手系（x 前、y 右、z 上）；KITTI 的激光雷达是 x 前、y 左、z 上，相机是 x 右、y 下、z 前；nuScenes 全局 / 自车 / 雷达是右手系，相机是 x 右、y 下、z 前。

## 17. 批量测试

工程树“仿真 → 批量测试”。一次选好要跑的组合，自动一个接一个运行，适合做对比实验：

- **场景**：不开封道，“测试场景”页的 4 个施工封道预设（封闭本车道、封闭左侧车道、连续两处封道、只剩一条车道）和 4 个动态目标预设（前车慢行、前车急刹、旁车切入、行人横穿）；勾几个都行。
- **出生点**：留空 = 当前的出生点；几个出生点用逗号分开，例如 `41, 3, 10`。
- **参数扫描**（可选）：选一个算法参数（“驾驶模式”页算法参数里列出的大写常数），填几个值（例如 `15, 20, 25`），每个值各跑一遍。
- **每次时长**：每一项运行多久（仿真时间）。
- **关闭渲染（更快）**：运行时 CARLA 不渲染画面、只算物理，约快 2.5 倍（实测路线跟随 30 s 仿真：16 s → 6.5 s）；运行中实时画面不更新。和“驾驶模式”页的“运行时关闭渲染”是同一个设置，单次运行也能用。要采集数据或算法要用相机传感器时自动不关，输出窗口说明原因；运行结束后恢复原来的设置；`run.json` 的 `no_render` 记下这次是否关了。
- 一共跑 场景 × 出生点 × 参数值 项；算法、车辆、CarSim / Chrono、仿真设置用各页现在的设置。点“**开始批量测试**”；“停止批量测试”会停掉当前这次并不再往下跑。
- **CARLA 中途崩溃或被关掉**：这一项记为“CARLA 断开”，批量测试暂停并提示；CARLA 的端口重新监听 20 s 后（给它加载地图的时间）自动重连，切回批量开始时的地图，把断开的那一项重跑一次，再接着往下跑。只看端口是否在监听，不会反复连接 CARLA（CARLA 0.9.16 被频繁连接会崩溃）。界面不会自己去启动 CARLA：桌面图标 / 远程启动器之外启动的 CARLA，要你手动重新启动。
- 每一项都是一次普通的运行，记录放在 `runs/batch_<时间>/` 里（运行记录目录下）。某一项没能启动（例如那里没有要封的车道），记为未通过并写出原因，接着跑下一项。
- **通过标准**（“测试项”下面的卡片）：每次运行结束时按它判定通过 / 未通过，不只是批量测试。默认三项：要跑完设定的时长、不能有碰撞、不能开出行车道；另外可以勾选指标的上下限：车道偏差均方根 / 最大 ≤、最小碰撞时间 TTC ≥、前方最小间距 ≥、最大加速度 / 减速度 ≤、最大纵向 jerk ≤（勾上时填入常用值，可改）。某一项没有数据时不算违反（例如前方一直没有接近的目标，TTC 为空）。判定写在输出窗口（“判定：未通过：最小碰撞时间 TTC 1.4 s < 2 s”）和 `run.json` 的 `verdict`，随工程保存。
- **结果**表：每一项的车道偏差、碰撞、出车道时间和是否通过（按通过标准；未通过的原因写在“说明”里）。每跑完一项都会更新报告：批量文件夹里的 `report.md`（表格）和 `report.csv`（Excel 能直接打开）。
- “**在‘运行对比’页打开这批运行**”：直接切到运行对比页，列出这一批的运行，勾选几次叠画曲线。

## 18. 运行对比

工程树“数据 → 运行对比”。每次运行都在运行记录目录（“驾驶模式”页，默认 `runs`）里留一个文件夹，这一页把它们列出来：时间、算法、车辆（CarSim / 模拟 CarSim / Chrono 宝马 / CARLA 物理）、地图、时长、车道偏差均方根、碰撞次数；鼠标停在时间上显示文件夹和结束原因。目录可以改，回车或🔄刷新。

- 勾选最多 4 次运行（A / B / C / D，各一种颜色；勾第 5 次时最早勾的那次取消）。
- **指标对比**：选中的运行并排列出时长、车道偏差均方根 / 最大、最大航向偏差、出车道时间、碰撞次数、前方最小间距、最小 TTC、最大加速 / 减速度、最大 jerk、最大侧向加速度、行驶距离；每一项最好的那次标绿；第一行是按通过标准的判定（未通过时鼠标停上去看原因）。
- **对比面板**（勾选后自动出现在底部面板里，也可以点“打开对比图”，或菜单“视图 → 运行对比图”）：轨迹（CarSim 全局坐标）、车速、车道偏差、控制算法的输出（真实 / 模拟 CarSim 是油门和方向盘转角，Chrono 宝马是 ax 和前轮转角）、以及算法 `self.debug` 里的一个量（下拉选择；没有时显示航向偏差），几次运行叠在一起。和其他面板一样可以拖动、浮动、放大。
- **时间轴**（对比面板顶部）：▶ 播放 / 暂停，拖动滑块跳到某一时刻，×0.5 ~ ×4 选播放速度。各条曲线上画一条竖线标出这一时刻，轨迹图上用圆点标出每次运行此刻的位置，下面逐行列出此刻的车速、车道偏差、控制输出和所选的 `self.debug` 量。
- **在 CARLA 里看这一刻（A）**：勾上后，主车被摆到 A 这次运行在时间轴时刻记录的位置和航向，拖动或播放时实时跟随，实时画面和视角一起动——可以回看当时车在哪、周围是什么。要求：已连接 CARLA、不在运行中、已生成主车、当前地图就是那次运行的地图（不是时会提示先加载哪张图）、记录里有自车的 X / Y / Yaw（默认就有）。回放时主车关掉物理，下一次运行会重新生成主车。
- **A 的输出**（“打开对比图”旁边）：打开一个窗口，显示 A 这次运行时“输出”窗口的全部内容（运行文件夹里的 `output.txt`：算法的 print 标 `[算法]`、警告、报错和调用栈、运行指标、结束原因，每行带时间），可以只看算法输出、一键复制。这个功能加入之前的运行没有这个文件。
- **车辆参数辨识（A）**（“指标对比”下面）：从 A 这次运行（CarSim、Chrono 宝马或模拟 CarSim）辨识 KMPPI 预测模型的前 / 后轴轮胎侧向力比例因子。填这台车的质量、横摆惯量、质心到前 / 后轴距离（CarSim 车辆参数里查），点 **辨识**：给出两个比例因子、拟合 R²、用到的样本数、最大侧向加速度和侧偏角。这次运行要有足够的转向（侧向加速度最大至少 1 m/s²，比如有弯道的路线），R² 低于 0.8 时会提示。点 **保存并用于 KMPPI** 写出车辆参数文件（默认 `controllers/kmppi/vehicle_identified.json`），当前算法是 KMPPI 时顺便把它的算法参数 `VEHICLE_JSON` 设成这个文件。这些输入随工程保存。
- 读运行记录由后端的单独线程处理，运行中也可以用；点数多时抽稀到 2000 点（保留最后一点）。

## 19. 常用操作流程

**A. 先不接 CarSim，跑通整条链路**
连接 → 车辆与视角（选车、生成主车）→ 驾驶模式（CarSim 联合仿真，展开“测试用驾驶方式”选路线跟随）→ CarSim 动力学（勾选“模拟 CarSim”）→ 实时画面（打开画面）→ 点顶部“运行”。

**B. 接入真实 CarSim**
在 CarSim 里配置好导出变量 → CarSim 动力学页：填 .sim 文件、python_carsim_env 目录，按 .sim 里的顺序填导出变量（看到绿色提示），点“检查 .sim”确认没有 ✗ → 驾驶模式页选“CarSim 联合仿真”，算法文件填你的 .py → 运行。保留“运行记录目录”（默认 `runs`），运行后打开这次的 `log.csv`，检查 `ego_X / ego_Y / ego_Yaw` 与 `Xo / Yo / Yaw` 是否一致。

**C. 采集一个小数据集**
地图与天气（选地图和天气）→ 交通流（例如 30 辆车、20 个行人）→ 车辆与视角（选车）→ 传感器套件（加载 nuScenes 预设）→ 驾驶模式（CARLA 物理 + CARLA 自动驾驶）→ 数据采集（打开、10 Hz、最多 200 帧）→ 运行。

**D. 测试避障算法（高速施工封道）**
连接 → 测试场景（点“切到 Town04 高速起点”，选一个预设，例如“封闭本车道（锥桶）”，按需改距离 / 车道）→ 场景信息（障碍物里确认勾了“施工锥桶 / 护栏”，碰撞选“停止运行”或“记录并继续”）→ 驾驶模式（你的算法）→ 运行。每次运行场景都一样，改完算法直接再运行对比；结果看这次运行文件夹的 `run.json`（碰撞次数、前方最小间距）和 `log_objects.csv`。
