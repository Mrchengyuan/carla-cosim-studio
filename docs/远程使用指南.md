# 远程使用指南（笔记本 + 云服务器）

笔记本只有集成显卡、跑不动 CARLA 时，用这种方式：**CARLA、后端和你的控制算法在云服务器（RTX 3090）上运行，笔记本只运行 CarSim 和界面**。
每次使用只要双击 **`启动远程仿真.exe`**（启动器）：它检查这台电脑、连接云服务器、启动 CarSim 服务，然后自动打开界面；和在本机使用一样操作。

> **测试说明**：启动器和界面程序在 Ubuntu 上编写 / 交叉编译。Linux 版启动器在服务器上用真实的 SSH 连接逐项测试过（`cosim_gui/tests/launcher_scenarios.py`，16 个场景）；
> Windows 版在 Wine 里跑通了完整流程（Windows 版 SSH、Python、界面都是 Windows 程序），但**还没有在实机 Windows 上运行过**。
> 遇到问题：点启动器右上角的“**日志**”打开日志文件夹，把 `remote_launch.log` 发出来（或在“运行日志”里点“复制”）。

## 1. 什么在哪里运行

```
你的 Windows 笔记本                                  云服务器（i.easy-ai.cloud）
┌──────────────────────────────┐                   ┌────────────────────────────────────┐
│ 界面 carla_cosim_studio.exe   │ ─┐                │ 后端（backend_server.py）            │
│                              │  │  一条 SSH 连接  │   你的控制算法 control()             │
│ CarSim 服务（后台）           │  ├──────────────▶ │   运行记录 runs/…                    │
│   CarSim 求解器（你的许可证）  │ ─┘ （只从笔记本    │ 改版 CARLA（场景、传感器、画面）       │
│ 启动器 启动远程仿真.exe        │     向外连接）     │                                      │
└──────────────────────────────┘                   └────────────────────────────────────┘
```

| 在哪里 | 运行什么 |
|---|---|
| **你的笔记本** | CarSim 求解器（在启动器开的 CarSim 服务里，用你的 CarSim 许可证）、界面、一条到云服务器的 SSH 连接 |
| **云服务器** | 改版 CARLA、后端、**你的控制算法**、运行记录和采集的数据 |

- 笔记本只向外连一条 SSH（端口 32122），不需要公网 IP，也不用开防火墙。
- 每一帧：云服务器上的算法算出油门 / 制动 / 方向盘 → 笔记本上的 CarSim 积分这一帧 → 结果回到云服务器，同步到 CARLA。**你的控制算法一行都不用改**：`control(exports, t, dt[, scene])` 的写法、CarSim 的坐标和单位都和本机使用时完全一样。
- 路径分两边：
  - `.sim` 文件、`python_carsim_env` 目录是**笔记本上的路径**（CarSim 在笔记本上运行）；
  - 控制算法文件、运行记录目录、采集输出目录是**云服务器上的路径**（算法和后端在云服务器上运行），相对路径从服务器上的 `carsim_carla_bridge` 目录算起。
- 控制算法文件放在云服务器上（例如 `~/carla_carsim/carsim_carla_bridge/controllers/`），用你平时登录服务器的方式（WinSCP、VS Code Remote-SSH 等）上传和修改。**启动包里的钥匙只能建立这一条连接**，不能登录服务器，也不能传文件。

## 2. 第一次使用（只做一次）

1. **解压启动包**：`CARLA_CoSim_Studio_Remote.zip` 右键 → **全部解压缩**，例如解压到 `D:\CARLA_CoSim_Studio_Remote`（路径里有空格、中文、括号都可以）。不要在压缩包里直接双击。解压后的文件夹：

   | 文件 | 作用 |
   |---|---|
   | `启动远程仿真.exe` | **启动器，每次双击它** |
   | `carla_cosim_studio.exe`、`fonts\` | 界面（由启动器打开） |
   | `remote_launcher.json` | 启动器的设置：云服务器的地址（固定），你选的 Python |
   | `cosim_studio_prefs.json` | 界面设置：连云服务器，不在本机启动后端 |
   | `service\` | CarSim 服务（`carsim_service.py` 等） |
   | `ssh\` | 连接云服务器的钥匙（`remote_key`）和服务器的指纹（`known_hosts`）。**不要发给别人** |
   | `使用说明.txt` | 本指南的简短版 |

2. **Python**：笔记本上要有 **64 位 Python 3.8 以上**（CarSim 求解器是 64 位的）。没有的话从 python.org 下载安装，安装时勾选 **Add python.exe to PATH**。
   启动器会自动找（先 `py -3`，再 `python`）；numpy 没装时，启动器里点“**安装 numpy**”即可（清华镜像，约 1 分钟）。
   已经按 [Windows 使用指南](Windows使用指南.md) 第 5 节建了虚拟环境、里面装好了 numpy 的，也可以用它：启动器“连接与设置”里 Python 一栏点“**选择…**”，选它的 `python.exe`（例如 `C:\carla-cosim-studio\venv\Scripts\python.exe`），会记住；“改回自动”恢复自动查找。
3. **python_carsim_env**：CarSim 的 Python 接口要在笔记本上。按 [Windows 使用指南 8.1](Windows使用指南.md#81-确认-python_carsim_env-能用) 把它放好并单独跑通一次（确认许可证、求解器 DLL 都没问题）。
4. **在 CarSim 里设置导入 / 导出变量**：按 [CarSim 导出变量清单](../carsim_carla_bridge/docs/CarSim导出变量清单.md) 添加导出变量，导入变量保持油门、制动、方向盘三个（和 [Windows 使用指南 8.2](Windows使用指南.md#82-在-carsim-里配置导出变量) 一样），生成 `.sim` 文件。**记下导出变量的顺序**。
5. **在界面里填 CarSim 的路径**（第一次用启动器打开界面之后）：在 **CarSim 动力学** 页
   - 取消“模拟 CarSim”；
   - `.sim 文件`：点输入框右边的文件夹图标“浏览…”，在弹出的 Windows 选择框里选中笔记本上的 `.sim`（也可以直接粘贴完整路径，例如 `C:\carla-cosim-studio\python_carsim_env\simfile.sim`）；
   - `python_carsim_env 目录`：**一般不用填**。`.sim` 放在 python_carsim_env 文件夹（或它的子文件夹）里时会自动找到，下方显示“（自动找到：.sim 所在的文件夹或它的上层）”；`.sim` 放在别处时，再用“浏览…”选 python_carsim_env 文件夹；
   - 导出变量按第 4 步的顺序填，看到绿色“必需变量齐全”。

   其余设置（车辆、驾驶模式、控制算法、传感器……）和本机使用一样，见 [界面操作手册](界面操作手册.md)。

## 3. 每次使用

1. 双击 **`启动远程仿真.exe`**，出现启动器窗口。
2. 启动器依次完成四步（窗口上方的四个圆圈，转圈 = 进行中，绿色对勾 = 完成）：
   1. **环境检查**：启动包文件、SSH 客户端、Python、numpy、本机端口。有问题的一项标红，下面写明怎么处理，能一键处理的有按钮（安装 numpy、选择 python.exe、结束旧连接……）。处理好点“重新检查”，再点“启动”。
   2. **云端连接**：连上云服务器，服务器上启动 CARLA（首次约 1 分钟，之后几秒）和后端。
   3. **CarSim 服务**：在笔记本上启动 CarSim 求解器服务，显示“已连上云端，等待运行”。
   4. **仿真界面**：云端就绪后自动打开界面，界面会自动连上。
3. 和本机一样在界面里操作，点 **运行**。
4. 用完直接**关闭界面**：启动器自动停止 CarSim 服务、断开云端（服务器上的后端随之停止），显示“仿真界面已关闭，云端连接已断开”。CARLA 留在服务器上继续运行，下次启动不用再等。再用时点“再次启动”，或关掉启动器。

网络断了一下时启动器会**自动重连**（最多 5 次），CarSim 服务和界面也会自己重新连上，不用重启。

| 连接与设置 | 云服务器（启动包里固定，服务器换了要用新的启动包）、本机端口、**Python**（自动查找或自己选）、运行记录在哪里 |
| 运行日志 | 启动器、云端、CarSim 服务、界面的输出，按来源筛选；“复制”把日志复制到剪贴板（请别人帮忙看问题时用） |

- 启动器开的程序（SSH、CarSim 服务、界面）都在后台运行，没有黑色命令行窗口；启动器被意外关掉（崩溃、任务管理器结束）时，它们也会一起结束。

## 5. 示例控制算法：路径跟踪（`controllers/path_follower.py`）

服务器上自带一个沿车道中心线行驶的算法，可以直接用来跑通流程，也可以照着写自己的算法：界面“控制算法”卡片里文件填 `controllers/path_follower.py`，入口 `Controller`。

- **道路信息全部来自 CARLA**：`scene["lane"]["center_rel"]`（车前 50 m 的车道中心线，自车坐标，“场景信息”页默认就勾选给算法）；车辆状态来自 CarSim 的导出变量。
- 横向：**纯跟踪（pure pursuit）**，前视距离约 1 s 的行程；急弯里补偿前后轮轨迹差（内轮差）。纯跟踪对转向滞后不敏感，适合事先不知道车辆动力学的情况（在转向滞后 0.35 s、60 km/h 的模型上仍然稳定）。方向盘传动比由 `Steer_SW` 和 `Steer_L1 / Steer_R1` 自动估计。
- 路口：车道信息取离车最近的车道，路口里可能跳到转弯车道上；算法记住上一段中心线，读数跳变或短暂没有车道信息时沿记住的路径走，岔路走转弯最少的那条。
- 纵向：定速（默认 40 km/h），前方有弯按侧向加速度 2 m/s² 提前降速。**不看红绿灯、不避让车辆和行人**。
- 按你的 CarSim 车辆改文件开头的几个常数：`WHEELBASE`（轴距）、`TARGET_KMH`（目标车速）、`BRAKE_MAX`（导入变量 2 的量程：制动踏板 0~1 时为 1，主缸压力 `IMP_PCON_BK` 时按 MPa，例如 8）。车身左右摆就加大 `LOOKAHEAD_TIME`，弯道切角大就减小（不要低于 0.8）。
- 测试：离线 21 项（含轮胎侧偏 + 转向滞后的动力学模型、路口车道跳变）；在 Town10 上 12 个出生点各 40 s、改版 CARLA 上 3 个出生点，车道中心偏差均方根 0.06~0.15 m，路口以外最大 0.54 m，无碰撞、不出车道。

## 6. 运行速度和结果

- 每一帧，云服务器和笔记本之间要来回一次（算法的控制量过去，CarSim 的结果回来）。网络往返时间约 30 ms 时，每秒最多约 30 帧；帧周期 0.02 s（50 Hz）的仿真就会比实时慢。**运行慢只影响等待的时间，不影响结果**：联合仿真是同步的，CARLA 每一帧都等 CarSim 算完这一帧才继续，不丢帧、不插值，结果和本机运行完全一样。
- 实时画面经过 JPEG 压缩后传到笔记本，画质略低于本机使用；采集保存的图像在服务器上，不受影响。
- 想快一些：用有线网络或信号好的 Wi-Fi；关掉界面里用不到的实时画面视图。

## 7. 运行结果在哪里

都在**云服务器**上（后端在那里运行）：

| 内容 | 位置（服务器上） |
|---|---|
| 运行记录（每次运行一个文件夹：`log.csv`、`run.json`、`config.json`、算法文件副本） | `~/carla_carsim/carsim_carla_bridge/runs/<时间_算法文件名>/`（“运行记录目录”保持默认 `runs` 时） |
| 数据采集 | “数据采集”页的输出目录，相对路径从 `~/carla_carsim/carsim_carla_bridge` 算起 |
| 后端的输出（出错时看它） | `~/.cache/carla_cosim_studio/remote_backend.log`（上一次的：`remote_backend.log.prev`） |

每次运行结束，界面的“输出”页会写出这次运行的文件夹。用你平时登录服务器的方式（WinSCP、scp 等）下载。笔记本上只有启动器的日志 `%LOCALAPPDATA%\carla_cosim_studio\remote_launch.log`（上一次的：`.prev`）。

## 8. 常见问题

启动器会把大多数问题直接写在窗口里（标红的检查项、红色状态条），并写明怎么处理。下面是更详细的说明。

| 现象 | 原因和解决 |
|---|---|
| 启动包文件：“缺少 …” | 没有解压，或只解压了一部分：把整个压缩包解压后，双击解压出来的 `启动远程仿真.exe` |
| SSH 客户端：“没有找到 ssh.exe” | 点“打开‘可选功能’设置” → 添加功能 → 安装“**OpenSSH 客户端**”（Windows 10 1809 以后都有），再点“重新检查” |
| Python：“没有找到 Python” | 点“下载 Python”安装 64 位 Python（勾选 Add python.exe to PATH）；已经装了的点“选择 python.exe…” |
| Python：“这是 32 位 Python” | CarSim 求解器是 64 位的：装 64 位 Python，或选择 64 位的 python.exe |
| numpy：“没有安装” | 点“安装 numpy”；失败时运行日志里有 pip 的输出（多半是网络问题） |
| 本机端口：“被占用：57120（ssh.exe）” | 上一次的连接还在：点“**结束旧连接**”。被别的程序占用时关掉那个程序（或重启电脑）再点“重新检查” |
| 没能连上云端服务器：“钥匙文件的权限太宽” | Windows 的 SSH 拒绝别人也能读的钥匙。启动器每次连接前会把钥匙复制到你自己的 `%LOCALAPPDATA%\carla_cosim_studio\ssh` 并设成只有你能读，一般不会出现；出现时把启动包解压到自己的文件夹（桌面、文档）再试 |
| 没能连上云端服务器：“云服务器没有接受启动包里的钥匙” | 服务器不认这把钥匙（被换过或撤销）：向管理员要新的启动包 |
| 没能连上云端服务器：“服务器的身份和启动包里记录的不一致” | 服务器重装过：向管理员要新的启动包。**不要**自己改 `known_hosts` |
| 没能连上云端服务器：“连不上服务器（超时）” / “找不到服务器地址” / “网络不通” | 先确认能上网；公司 / 学校网络可能拦截对外的 32122 端口，换个网络（如手机热点）试试；云服务器可能已关机或到期 |
| 云端的 `[错误] 服务器上的端口 3000 被其他程序占用` 或 `CARLA 没有启动成功` | 服务器上的问题，点运行日志的“复制”，发给管理员 |
| “云端一直没有就绪” | 7 分钟内 CARLA 或后端没有启动成功：复制运行日志发给管理员（服务器上的记录：`~/.cache/carla_cosim_studio/remote_backend.log`） |
| “CarSim 服务停止了” | 运行日志“CarSim 服务”里有原因（例如 python_carsim_env 的错误）；处理后点“重启 CarSim 服务” |
| 运行出错：“**Windows 上的 CarSim 服务没有连上云端**” | CarSim 服务还没显示“已连上云端”就点了运行，或它停止了：看启动器里 CarSim 服务一步的状态 |
| CarSim 服务：“另一台电脑的 CarSim 服务连上了云端” | 同一个启动包在两台电脑上同时用了，云端只用最新连上的那个 |
| 运行出错：“与 Windows 上的 CarSim 服务的连接断开了（……）” | 运行中网络断了或笔记本睡眠了。这次运行已经结束（CARLA 里不留东西）；启动器会自动重连，重新连上后再运行 |
| CarSim 的报错（找不到 .sim / DLL、许可证错误） | 显示在界面和启动器的运行日志里，是**笔记本上**的问题：检查 CarSim 页的路径是不是笔记本上的路径、许可证服务是否在运行；先按 [Windows 使用指南 8.1](Windows使用指南.md#81-确认-python_carsim_env-能用) 单独跑通 python_carsim_env |
| 运行比本机慢很多 | 见 [第 6 节](#6-运行速度和结果)：主要是网络往返时间，结果仍然精确（同步运行） |
| 视口上方红色提示“CARLA 服务器已退出或连不上” | 服务器上的 CARLA 退出了：关掉界面（启动器会断开），点“再次启动”，服务器会重新启动 CARLA（约 1 分钟） |
| 界面里点“重启后端” | 服务器上的后端会重启，界面几秒后自动重新连上 |
| 界面打不开，运行日志“仿真界面”里有 `GLFW` 或 OpenGL 的报错 | 显卡驱动太旧，不支持 OpenGL 3：更新显卡驱动（Intel 核显到 Intel 官网下载） |
| 更新启动包 | 先关掉启动器，删掉旧文件夹，再解压新的 |

## 9. 给服务器管理员

服务器端（本仓库，`~/carla_carsim`）：

- `scripts/remote_session.sh`：SSH 连接上来时运行的程序（钥匙的 forced command）。按需启动改版 CARLA（tmux 会话 `carla_mod`，和 `start_studio.sh mod` 一样；只看端口表判断 CARLA 是否在运行，从不“连一下试试”），在 127.0.0.1:57120（界面）和 57121（CarSim 服务）上运行后端，后端退出就重新启动（退出码 3 是界面的“重启后端”）；连接断开时停止后端（SIGTERM，10 秒后 SIGKILL），CARLA 留着；新的连接替换旧的。可以手动运行来测试，Ctrl+D 或 Ctrl+C 结束。
- 安装钥匙（只做一次；再运行不会重复添加，也不改 `authorized_keys` 里的其他行）：
  ```bash
  ~/carla_carsim/scripts/install_remote_key.sh            # 默认 ~/.ssh/authorized_keys
  ```
  生成 `~/.config/carla_cosim_studio/remote_key`（ed25519），在 `authorized_keys` 里加一行
  `restrict,port-forwarding,permitopen="127.0.0.1:57120",permitopen="127.0.0.1:57121",permitlisten="127.0.0.1:1",command=".../scripts/remote_session.sh" ssh-ed25519 … carla-cosim-remote`：
  这把钥匙不能开 shell、不能运行别的命令、不能传文件、只能转发这两个端口（`permitlisten` 让它不能反向转发 `ssh -R`：用户永远不能监听端口 1）。撤销：删掉这一行。

  ssh-keyscan -p 32122 i.easy-ai.cloud > kh.txt        # 在服务器以外的电脑上运行，把 kh.txt 拷过来
