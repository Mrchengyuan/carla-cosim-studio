# 远程使用指南（笔记本 + 云服务器）

笔记本只有集成显卡、跑不动 CARLA 时，用这种方式：**CARLA、后端和你的控制算法在云服务器（RTX 3090）上运行，笔记本只运行 CarSim 和界面**。
每次使用只要双击一个启动脚本，界面打开时已经连着云服务器；和在本机使用一样操作。

> **测试说明**：启动脚本和界面程序是在 Ubuntu 上编写 / 交叉编译的，服务器端已经测试，**Windows 这一端还没有在实机上运行过**。
> 遇到问题请把启动窗口里的提示和 `%LOCALAPPDATA%\carla_cosim_studio\remote_launch.log` 发出来。

## 1. 什么在哪里运行

```
你的 Windows 笔记本                                  云服务器（i.easy-ai.cloud）
┌──────────────────────────────┐                   ┌────────────────────────────────────┐
│ 界面 carla_cosim_studio.exe   │ ─┐                │ 后端（backend_server.py）            │
│                              │  │  一条 SSH 连接  │   你的控制算法 control()             │
│ “CarSim 服务”窗口             │  ├──────────────▶ │   运行记录 runs/…                    │
│   CarSim 求解器（你的许可证）  │ ─┘ （只从笔记本    │ 改版 CARLA（场景、传感器、画面）       │
│ “云端连接”窗口（ssh）          │     向外连接）     │                                      │
└──────────────────────────────┘                   └────────────────────────────────────┘
```

| 在哪里 | 运行什么 |
|---|---|
| **你的笔记本** | CarSim 求解器（在“CarSim 服务”窗口里，用你的 CarSim 许可证）、界面、一条到云服务器的 SSH 连接 |
| **云服务器** | 改版 CARLA、后端、**你的控制算法**、运行记录和采集的数据 |

- 笔记本只向外连一条 SSH（端口 32122），不需要公网 IP，也不用开防火墙。
- 每一帧：云服务器上的算法算出油门 / 制动 / 方向盘 → 笔记本上的 CarSim 积分这一帧 → 结果回到云服务器，同步到 CARLA。**你的控制算法一行都不用改**：`control(exports, t, dt[, scene])` 的写法、CarSim 的坐标和单位都和本机使用时完全一样。
- 路径分两边：
  - `.sim` 文件、`python_carsim_env` 目录是**笔记本上的路径**（CarSim 在笔记本上运行）；
  - 控制算法文件、运行记录目录、采集输出目录是**云服务器上的路径**（算法和后端在云服务器上运行），相对路径从服务器上的 `carsim_carla_bridge` 目录算起。
- 控制算法文件放在云服务器上（例如 `~/carla_carsim/carsim_carla_bridge/controllers/`），用你平时登录服务器的方式（WinSCP、VS Code Remote-SSH 等）上传和修改。**启动包里的钥匙只能建立这一条连接**，不能登录服务器，也不能传文件。

## 2. 第一次使用（只做一次）

1. **解压启动包**：`CARLA_CoSim_Studio_Remote.zip` 右键 → **全部解压缩**，例如解压到 `D:\CARLA_CoSim_Studio_Remote`（路径里有空格、中文、括号都可以）。不要在压缩包里直接双击。解压后的文件夹：

   | 文件 | 作用 |
   |---|---|
   | `启动远程仿真.bat` | 每次双击它 |
   | `carla_cosim_studio.exe`、`fonts\` | 界面 |
   | `cosim_studio_prefs.json` | 界面设置：连云服务器，不在本机启动后端 |
   | `service\` | CarSim 服务（`carsim_service.py` 等） |
   | `ssh\` | 连接云服务器的钥匙（`remote_key`）和服务器的指纹（`known_hosts`）。**不要发给别人** |
   | `使用说明.txt` | 本指南的简短版 |

2. **Python**：笔记本上要有 **64 位 Python 3.8 以上**（CarSim 求解器是 64 位的），并装好 numpy：
   ```bat
   py -3 -m pip install numpy
   ```
   已经按 [Windows 使用指南](Windows使用指南.md) 第 5 节建了虚拟环境、里面装好了 numpy 的，也可以用它：用记事本打开 `启动远程仿真.bat`，在开头的 `set "CARSIM_PYTHON="` 里填它的完整路径，例如 `set "CARSIM_PYTHON=C:\carla-cosim-studio\venv\Scripts\python.exe"`，保存时编码选“UTF-8”（不要选“带有 BOM 的 UTF-8”）。
3. **python_carsim_env**：CarSim 的 Python 接口要在笔记本上。按 [Windows 使用指南 8.1](Windows使用指南.md#81-确认-python_carsim_env-能用) 把它放好并单独跑通一次（确认许可证、求解器 DLL 都没问题）。
4. **在 CarSim 里设置导入 / 导出变量**：按 [CarSim 导出变量清单](../carsim_carla_bridge/docs/CarSim导出变量清单.md) 添加导出变量，导入变量保持油门、制动、方向盘三个（和 [Windows 使用指南 8.2](Windows使用指南.md#82-在-carsim-里配置导出变量) 一样），生成 `.sim` 文件。**记下导出变量的顺序**。
5. **在界面里填 CarSim 的路径**（第一次双击启动脚本、界面打开之后）：在 **CarSim 动力学** 页
   - 取消“模拟 CarSim”；
   - `.sim 文件`：笔记本上的路径，例如 `C:\carla-cosim-studio\python_carsim_env\simfile.sim`；
   - `python_carsim_env 目录`：笔记本上的路径，例如 `C:\carla-cosim-studio\python_carsim_env`；
   - 导出变量按第 4 步的顺序填，看到绿色“必需变量齐全”。

   其余设置（车辆、驾驶模式、控制算法、传感器……）和本机使用一样，见 [界面操作手册](界面操作手册.md)。

## 3. 每次使用

1. 双击 **`启动远程仿真.bat`**。
2. 依次出现：启动窗口 →“**云端连接**”窗口 →“**CarSim 服务**”窗口 → 界面。
3. 看“云端连接”窗口：
   ```
   已连上云端服务器（…）
   正在启动 CARLA（首次约 1 分钟）…     ← 服务器上的 CARLA 已经在运行时没有这一行
   CARLA 已就绪
   后端已就绪
   就绪
   ```
   出现 **就绪** 后界面会自动连上（CARLA 刚启动时约 1 分钟，之后几秒）。“CarSim 服务”窗口显示 **已连上云端**。
4. 和本机一样操作，点 **运行**。
5. 用完直接**关闭界面**：“云端连接”和“CarSim 服务”窗口会自动关闭，服务器上的后端随之停止。CARLA 留在服务器上继续运行，下次启动不用再等。

## 4. 这几个窗口是什么

| 窗口 | 是什么 | 注意 |
|---|---|---|
| **启动远程仿真**（第一个黑色窗口） | 启动脚本本身：检查文件、Python、钥匙，依次打开下面的窗口，界面关闭后把它们关掉 | **界面开着时不要关它**，否则界面关闭后另外两个窗口要自己关 |
| **云端连接** | 到云服务器的 SSH 连接（界面和 CarSim 服务的数据都走它），显示服务器上的启动进度 | 关掉它就断开了云端，界面会显示后端未连接 |
| **CarSim 服务** | 在笔记本上运行 CarSim 求解器的 Python 程序，每次运行显示“运行开始 / 运行结束”，CarSim 的报错也显示在这里 | 关掉它，运行会报“Windows 上的 CarSim 服务没有连上云端” |
| **CARLA CoSim Studio** | 界面 | 关闭它 = 结束这次使用 |

> 不要在“云端连接”“CarSim 服务”窗口里用鼠标选中文字：Windows 命令行窗口处于“选择”状态时（标题栏出现“选择”），里面的程序会暂停，运行随之卡住。按 **Esc** 就恢复。

## 5. 运行速度和结果

- 每一帧，云服务器和笔记本之间要来回一次（算法的控制量过去，CarSim 的结果回来）。网络往返时间约 30 ms 时，每秒最多约 30 帧；帧周期 0.02 s（50 Hz）的仿真就会比实时慢。**运行慢只影响等待的时间，不影响结果**：联合仿真是同步的，CARLA 每一帧都等 CarSim 算完这一帧才继续，不丢帧、不插值，结果和本机运行完全一样。
- 实时画面经过 JPEG 压缩后传到笔记本，画质略低于本机使用；采集保存的图像在服务器上，不受影响。
- 想快一些：用有线网络或信号好的 Wi-Fi；关掉界面里用不到的实时画面视图。

## 6. 运行结果在哪里

都在**云服务器**上（后端在那里运行）：

| 内容 | 位置（服务器上） |
|---|---|
| 运行记录（每次运行一个文件夹：`log.csv`、`run.json`、`config.json`、算法文件副本） | `~/carla_carsim/carsim_carla_bridge/runs/<时间_算法文件名>/`（“运行记录目录”保持默认 `runs` 时） |
| 数据采集 | “数据采集”页的输出目录，相对路径从 `~/carla_carsim/carsim_carla_bridge` 算起 |
| 后端的输出（出错时看它） | `~/.cache/carla_cosim_studio/remote_backend.log`（上一次的：`remote_backend.log.prev`） |

每次运行结束，界面的“输出”页会写出这次运行的文件夹。用你平时登录服务器的方式（WinSCP、scp 等）下载。笔记本上只有启动记录 `%LOCALAPPDATA%\carla_cosim_studio\remote_launch.log`。

## 7. 常见问题

| 现象 | 原因和解决 |
|---|---|
| 启动窗口：“找不到启动包里的文件” | 没有解压，或只解压了一部分：把整个压缩包解压后，双击解压出来的 `启动远程仿真.bat` |
| 启动窗口：“找不到 Windows 自带的 SSH 客户端” | 设置 → 应用 → 可选功能 → 添加功能 → 安装“**OpenSSH 客户端**”（Windows 10 1809 以后都有） |
| 启动窗口：“找不到 Python” / “里没有 numpy” | 按第 2 节第 2 步装 64 位 Python 和 numpy，或在 `CARSIM_PYTHON` 填已装好 numpy 的 python.exe |
| “云端连接”窗口：`UNPROTECTED PRIVATE KEY FILE`、`bad permissions`、`Load key ... Permission denied` | **钥匙文件的权限**：Windows 的 SSH 拒绝别人也能读的钥匙。启动脚本每次都会把 `ssh\remote_key` 改成只有你能读；仍然出现时，多半是解压到了 U 盘 / 移动硬盘（FAT32、exFAT 没有权限设置）或网络盘：把文件夹放到 `C:` 或 `D:` 盘再试。也可以手动设置：在 `ssh` 文件夹里打开命令提示符，运行 `icacls remote_key /inheritance:r /grant:r "%USERNAME%:R"` |
| “云端连接”窗口：`Permission denied (publickey)` | 服务器不认这把钥匙（钥匙被换过或被撤销）：向管理员要新的启动包 |
| “云端连接”窗口：`Host key verification failed` | 服务器的指纹变了（服务器重装过）：向管理员要新的启动包。**不要**自己改 `known_hosts` |
| 启动窗口：“120 秒内没有连上云端”；“云端连接”窗口：`Connection timed out` / `Could not resolve hostname` | 网络不通：先确认能上网；公司 / 学校网络可能拦截对外的 32122 端口，换个网络（如手机热点）试试 |
| 启动窗口：“端口 57120 已被占用”；或“云端连接”窗口：`Could not request local forwarding` | 上一次的“云端连接”窗口还开着（例如先关了启动窗口）：关掉旧的“云端连接”“CarSim 服务”窗口和界面再双击；还不行就重启电脑 |
| “云端连接”窗口：`[错误] 服务器上的端口 3000 被其他程序占用` 或 `CARLA 没有启动成功` | 服务器上的问题，把这几行发给管理员 |
| 界面一直显示后端未连接 | “云端连接”窗口还没显示“就绪”（CARLA 刚启动，约 1 分钟）就等一等；窗口里显示“后端已退出……”时把 `remote_backend.log` 发给管理员 |
| 运行出错：“**Windows 上的 CarSim 服务没有连上云端**：请在 Windows 上双击启动脚本……” | 后端找不到笔记本上的 CarSim 服务：“CarSim 服务”窗口被关了，或它还没显示“已连上云端”。关掉界面，重新双击 `启动远程仿真.bat`，等“CarSim 服务”窗口显示“已连上云端”后再点运行 |
| “CarSim 服务”窗口：“另一个 CarSim 服务（…）连上了云端，这个窗口不再连接” | 同时开了两个 CarSim 服务（例如旧的启动窗口没关），云端只用最新连上的那个，旧的这个自动退出，关掉它即可；运行不受影响 |
| 运行出错：“与 Windows 上的 CarSim 服务的连接断开了（……）” | 运行中网络断了、笔记本睡眠了，或“CarSim 服务”窗口被关了。这次运行已经结束（CARLA 里不留东西）；网络恢复后重新双击启动脚本再运行 |
| CarSim 的报错（找不到 .sim / DLL、许可证错误） | 显示在“CarSim 服务”窗口和界面里，是**笔记本上**的问题：检查 CarSim 页的路径是不是笔记本上的路径、许可证服务是否在运行；先按 [Windows 使用指南 8.1](Windows使用指南.md#81-确认-python_carsim_env-能用) 单独跑通 python_carsim_env |
| 运行比本机慢很多 | 见 [第 5 节](#5-运行速度和结果)：主要是网络往返时间，结果仍然精确（同步运行） |
| 运行卡住不动，某个命令行窗口标题有“选择” | 窗口里被选中了文字（程序暂停）：点一下那个窗口按 **Esc** |
| 视口上方红色提示“CARLA 服务器已退出或连不上” | 服务器上的 CARLA 退出了：关掉界面，重新双击启动脚本，服务器会重新启动 CARLA（约 1 分钟） |
| 界面里点“重启后端” | 服务器上的后端会重启，界面几秒后自动重新连上 |
| 更新启动包 | 先删掉旧文件夹（钥匙文件是只读的，直接覆盖解压会失败），再解压新的 |

## 8. 给服务器管理员

服务器端（本仓库，`~/carla_carsim`）：

- `scripts/remote_session.sh`：SSH 连接上来时运行的程序（钥匙的 forced command）。按需启动改版 CARLA（tmux 会话 `carla_mod`，和 `start_studio.sh mod` 一样；只看端口表判断 CARLA 是否在运行，从不“连一下试试”），在 127.0.0.1:57120（界面）和 57121（CarSim 服务）上运行后端，后端退出就重新启动（退出码 3 是界面的“重启后端”）；连接断开时停止后端（SIGTERM，10 秒后 SIGKILL），CARLA 留着；新的连接替换旧的。可以手动运行来测试，Ctrl+D 或 Ctrl+C 结束。
- 安装钥匙（只做一次；再运行不会重复添加，也不改 `authorized_keys` 里的其他行）：
  ```bash
  ~/carla_carsim/scripts/install_remote_key.sh            # 默认 ~/.ssh/authorized_keys
  ```
  生成 `~/.config/carla_cosim_studio/remote_key`（ed25519），在 `authorized_keys` 里加一行
  `restrict,port-forwarding,permitopen="127.0.0.1:57120",permitopen="127.0.0.1:57121",permitlisten="127.0.0.1:1",command=".../scripts/remote_session.sh" ssh-ed25519 … carla-cosim-remote`：
  这把钥匙不能开 shell、不能运行别的命令、不能传文件、只能转发这两个端口（`permitlisten` 让它不能反向转发 `ssh -R`：用户永远不能监听端口 1）。撤销：删掉这一行。
- 打包（Windows 版界面由 MinGW 在这里编译）：
  ```bash
  ssh-keyscan -p 32122 i.easy-ai.cloud > kh.txt        # 在服务器以外的电脑上运行，把 kh.txt 拷过来
  ~/carla_carsim/scripts/build_remote_package.sh --known-hosts kh.txt
  ```
  生成 `~/carla_cosim_remote_pkg/CARLA_CoSim_Studio_Remote.zip`（`--out` 改位置，不能在仓库里）。压缩包里有私钥：私下发给用户，不要提交到 git。
